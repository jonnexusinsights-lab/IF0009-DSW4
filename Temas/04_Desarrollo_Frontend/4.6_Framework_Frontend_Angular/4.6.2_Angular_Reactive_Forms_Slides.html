¿Por qué Formularios Reactivos?

Para aplicaciones de nivel empresarial, los formularios básicos (Template-Driven) no son suficientes. Los Formularios Reactivos proporcionan:
  • Gestión del Estado en la Clase: La lógica está en TypeScript, no en el HTML.
  • Inmutabilidad: Cada cambio devuelve un nuevo estado de forma reactiva.
  • Seguridad de Tipos (Angular 14+): Validaciones de tipos estrictas (Type Safety).
  • Testeabilidad: Es más fácil escribir pruebas unitarias para la lógica del formulario.

🧱 Componentes Básicos

Los bloques de construcción son:
  1. FormControl: Rastrea un único campo de input (ej. nombre).
  2. FormGroup: Agrupa múltiples controles relacionados (ej. datos personales).
  3. FormArray: Maneja una lista dinámica de controles que crece o se reduce.
  4. FormBuilder: Un servicio utilitario (inject(FormBuilder)) que reduce el código repetitivo al crear estos elementos.

🛡️ Typed Forms (Formularios Tipados)

Desde Angular 14, si usamos un FormBuilder, TypeScript infiere y restringe automáticamente la estructura del formulario. 
import { Component, inject } from '@angular/core';
import { FormBuilder, Validators } from '@angular/forms';

export class RegistroComponent {
  private fb = inject(FormBuilder);

  // TypeScript sabe que 'edad' es number
  registroForm = this.fb.group({
    nombre: ['', Validators.required],
    edad: [0, Validators.min(18)]
  });
}
Si intentamos hacer registroForm.patchValue({ edad: "veinte" }), el compilador fallará.

✅ Validadores (Synchronous y Asynchronous)

  • Validadores Síncronos: Revisan el control instantáneamente en memoria.
    • Ejemplos: Validators.required, Validators.email, Validators.pattern.
  • Validadores Asíncronos: Consultan a un servidor (API) y retornan un Observable o Promise.
    • Ejemplo: Comprobar si un username o un email ya están registrados en la base de datos.

🔗 Validaciones de Campos Cruzados (Cross-Field)

A veces, validar un campo depende de otro campo (ej. Contraseña vs Confirmar Contraseña). Esto se aplica a nivel de FormGroup, no de FormControl. 
function passwordMatchValidator(g: AbstractControl): ValidationErrors | null {
  const pwd = g.get('password')?.value;
  const confirm = g.get('confirmPassword')?.value;
  return pwd === confirm ? null : { mismatch: true };
}

// Implementación:
this.fb.group({
  password: ['', Validators.required],
  confirmPassword: ['', Validators.required]
}, { validators: passwordMatchValidator });

➕ Formularios Dinámicos con FormArray

Para listas dinámicas (ej. múltiples roles o habilidades de un usuario), utilizamos FormArray. 
get habilidades() {
  return this.registroForm.get('habilidades') as FormArray;
}

agregarHabilidad() {
  this.habilidades.push(this.fb.control('', Validators.required));
}

removerHabilidad(index: number) {
  this.habilidades.removeAt(index);
}
En el HTML se itera sobre este arreglo usando el moderno control de flujo @for.

📡 Integrando Formularios con Signals (Angular 16+)

Las Signals son el nuevo estándar de reactividad fina en Angular. Podemos convertir los flujos reactivos del formulario (valueChanges) directamente a Signals para optimizar el renderizado y eliminar subscripciones (subscribe()). 
import { toSignal } from '@angular/core/rxjs-interop';

export class RegistroComponent {
  // ... creación del formulario ...
  
  // Convierte los cambios del formulario en una Signal reactiva
  formValues = toSignal(this.registroForm.valueChanges, 
                        { initialValue: this.registroForm.value });

  // Computed signal que reacciona instántaneamente
  progreso = computed(() => {
    return this.formValues().nombre ? 'Progreso: 50%' : 'Progreso: 0%';
  });
}

💻 Master Class: Práctica de Interfaz Gráfica

En el HTML de nuestro formulario, usamos las directivas [formGroup] y formControlName para enlazar el modelo de TypeScript. Además, utilizamos el nuevo @if para mostrar errores visualmente. 
<form [formGroup]="registroForm" (ngSubmit)="onSubmit()">
  
  <input type="email" formControlName="email">
  
  @if (registroForm.get('email')?.errors?.['email'] && 
       registroForm.get('email')?.touched) {
    <span class="error">Formato de correo incorrecto.</span>
  }

  <button type="submit" [disabled]="registroForm.invalid">
    Guardar
  </button>
</form>
touched garantiza que el error solo se muestre si el usuario ya visitó el campo.

🏁 Conclusión y Reto

  • Los Formularios Reactivos separan la lógica de validación de la vista.
  • Typed Forms evitan errores catastróficos en tiempo de ejecución.
  • Signals se acoplan perfectamente para proporcionar una UI altamente reactiva.
