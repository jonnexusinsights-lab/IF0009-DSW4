# Tema 4.6.2: Angular Framework - Formularios Reactivos (Reactive Forms)

## 1. Introducción a los Formularios Reactivos

En el ecosistema de Angular, existen dos enfoques principales para manejar la captura de datos de los usuarios: los formularios basados en plantillas (Template-Driven Forms) y los **Formularios Reactivos (Reactive Forms)**. Para aplicaciones empresariales complejas, escalables y con validaciones dinámicas, los Formularios Reactivos son el estándar de la industria.

A diferencia de los formularios basados en plantillas, donde la lógica se define predominantemente en el HTML (usando directivas como `[(ngModel)]`), los Formularios Reactivos trasladan la construcción del modelo de datos y la lógica de validación al **componente de TypeScript (clase)**.

### Ventajas de los Formularios Reactivos:
- **Modelo Explícito (Stateful):** El estado del formulario se gestiona explícitamente en la clase, lo que permite observar cambios en tiempo real.
- **Inmutabilidad:** Cada vez que el valor de un campo cambia, Angular devuelve un nuevo estado, lo que facilita la predicción y el rastreo de datos.
- **Validación Síncrona y Asíncrona Robusta:** Permite crear validadores complejos, incluso aquellos que requieren consultar un servidor.
- **Tipado Fuerte (Angular 14+):** Se garantiza la seguridad de tipos (Type Safety) en tiempo de compilación.

---

## 2. Componentes Fundamentales: FormControl, FormGroup y FormBuilder

El bloque de construcción más básico de un formulario es la clase `FormControl`.

*   **`FormControl`**: Rastrea el valor y el estado de validación de un control de formulario individual (ej: un input de texto).
*   **`FormGroup`**: Rastrea el valor y el estado de validación de un grupo de instancias de `FormControl`. Se utiliza para agrupar campos relacionados (ej: un formulario de registro o una sección de dirección).
*   **`FormArray`**: Una variante de `FormGroup` utilizada para manejar arreglos dinámicos de controles, donde la cantidad de campos puede crecer o disminuir según las acciones del usuario.
*   **`FormBuilder` (`inject(NonNullableFormBuilder)` o `inject(FormBuilder)`)**: Un servicio sintáctico y utilitario para crear instancias de controles, grupos y arreglos con menos código boilerplate.

---

## 3. Typed Forms (Angular 14+)

Desde Angular 14, los formularios reactivos son **estrictamente tipados** por defecto. Esto significa que TypeScript conoce la estructura exacta de su formulario. Si su formulario requiere que un campo `edad` sea un `number`, TypeScript emitirá un error si intenta asignarle un `string`.

Ejemplo de definición con `FormBuilder`:

```typescript
import { Component, inject } from '@angular/core';
import { ReactiveFormsModule, FormBuilder, Validators } from '@angular/forms';

@Component({
  selector: 'app-registro',
  standalone: true,
  imports: [ReactiveFormsModule],
  templateUrl: './registro.component.html'
})
export class RegistroComponent {
  private fb = inject(FormBuilder);

  // El tipo se infiere automáticamente: { nombre: string, email: string }
  registroForm = this.fb.group({
    nombre: ['', [Validators.required, Validators.minLength(3)]],
    email: ['', [Validators.required, Validators.email]]
  });
}
```

## 4. Validadores (Synchronous y Asynchronous)

### 4.1 Validadores Síncronos
Son funciones que toman un `AbstractControl` e inmediatamente retornan un objeto de error (si falla) o `null` (si es válido).
Ejemplos integrados: `Validators.required`, `Validators.min()`, `Validators.pattern()`.

### 4.2 Validadores Asíncronos
Son funciones que toman un control pero retornan una Promesa (`Promise`) o un Observable (`Observable`) que emite un objeto de error o `null`. Son vitales para acciones como comprobar si un nombre de usuario ya existe en la base de datos consultando a una API.

```typescript
// validador asincrono ejemplo
verificarUsuarioExistente(usuarioService: UsuarioService): AsyncValidatorFn {
  return (control: AbstractControl): Observable<ValidationErrors | null> => {
    return usuarioService.verificarEmail(control.value).pipe(
      map(existe => (existe ? { emailTomado: true } : null)),
      catchError(() => of(null))
    );
  };
}
```

## 5. Validaciones de Campos Cruzados (Cross-Field Validations)

A menudo, la validación de un campo depende del valor de otro (ej: confirmar que la contraseña y la confirmación de contraseña coinciden). Este tipo de validación se aplica al **`FormGroup`**, no a un `FormControl` individual.

```typescript
export function passwordMatchValidator(g: AbstractControl): ValidationErrors | null {
  const password = g.get('password')?.value;
  const confirmPassword = g.get('confirmPassword')?.value;

  return password === confirmPassword ? null : { mismatch: true };
}

// Aplicación en el FormGroup:
this.fb.group({
  password: ['', Validators.required],
  confirmPassword: ['', Validators.required]
}, { validators: passwordMatchValidator });
```

## 6. Formularios Dinámicos con FormArray

`FormArray` es excelente para listas dinámicas (ej: agregar múltiples teléfonos o múltiples direcciones).

```typescript
get telefonos() {
  return this.registroForm.get('telefonos') as FormArray;
}

agregarTelefono() {
  this.telefonos.push(this.fb.control('', Validators.required));
}

removerTelefono(index: number) {
  this.telefonos.removeAt(index);
}
```

## 7. Integración de Formularios Reactivos con Signals (Angular 16+)

Las **Signals** de Angular permiten una reactividad fina. Podemos combinar los eventos de cambio de valor del formulario (`valueChanges`) con Signals usando la función `toSignal()` de `@angular/core/rxjs-interop` para reaccionar a cambios en la UI de manera altamente performante sin suscripciones manuales (`subscribe()`).

```typescript
import { toSignal } from '@angular/core/rxjs-interop';
import { computed } from '@angular/core';

export class RegistroComponent {
  // ...
  registroForm = this.fb.group({
    nombre: ['']
  });

  // Convertimos el observable valueChanges en una Signal
  formValues = toSignal(this.registroForm.valueChanges, { initialValue: this.registroForm.value });

  // Computed signal reacciona cuando formValues cambia
  saludoDinamico = computed(() => {
    const nombre = this.formValues().nombre;
    return nombre ? `¡Hola, ${nombre}!` : 'Por favor ingrese su nombre.';
  });
}
```

## 8. Master Class: Construyendo un Formulario de Registro Complejo

A continuación, implementaremos un formulario de registro completo utilizando todos los conceptos expuestos.

### Componente de TypeScript (Lógica)

```typescript
import { Component, inject } from '@angular/core';
import { FormBuilder, ReactiveFormsModule, Validators, FormArray, AbstractControl, ValidationErrors } from '@angular/forms';
import { CommonModule } from '@angular/common';

// Validador de validación cruzada
function passwordMatchValidator(control: AbstractControl): ValidationErrors | null {
  const password = control.get('password')?.value;
  const confirmPassword = control.get('confirmPassword')?.value;
  return password === confirmPassword ? null : { mismatch: true };
}

@Component({
  selector: 'app-registro-complejo',
  standalone: true,
  imports: [CommonModule, ReactiveFormsModule],
  templateUrl: './registro-complejo.component.html',
  styleUrls: ['./registro-complejo.component.css']
})
export class RegistroComplejoComponent {
  private fb = inject(FormBuilder);

  registroForm = this.fb.group({
    datosPersonales: this.fb.group({
      nombre: ['', [Validators.required, Validators.minLength(3)]],
      email: ['', [Validators.required, Validators.email]],
    }),
    seguridad: this.fb.group({
      password: ['', [Validators.required, Validators.minLength(6)]],
      confirmPassword: ['', Validators.required]
    }, { validators: passwordMatchValidator }),
    habilidades: this.fb.array([
      this.fb.control('', Validators.required) // Iniciamos con un campo
    ])
  });

  // Getter para facilitar el acceso al FormArray en el HTML
  get habilidades() {
    return this.registroForm.get('habilidades') as FormArray;
  }

  agregarHabilidad() {
    this.habilidades.push(this.fb.control('', Validators.required));
  }

  removerHabilidad(index: number) {
    this.habilidades.removeAt(index);
  }

  onSubmit() {
    if (this.registroForm.valid) {
      console.log('Formulario enviado con éxito:', this.registroForm.value);
      // Aquí llamaría a un servicio HTTP
    } else {
      this.registroForm.markAllAsTouched(); // Muestra todos los errores si el usuario intenta enviar vacio
    }
  }
}
```

### Plantilla HTML (Vista y Manejo de Errores)

```html
<form [formGroup]="registroForm" (ngSubmit)="onSubmit()" class="formulario-premium">
  <h2>Registro de Usuario</h2>

  <!-- Grupo: Datos Personales -->
  <fieldset formGroupName="datosPersonales">
    <legend>Datos Personales</legend>
    
    <div class="form-group">
      <label>Nombre:</label>
      <input type="text" formControlName="nombre">
      <!-- UI de Errores -->
      @if (registroForm.get('datosPersonales.nombre')?.invalid && registroForm.get('datosPersonales.nombre')?.touched) {
        <span class="error-msg">El nombre es requerido (min. 3 caracteres).</span>
      }
    </div>

    <div class="form-group">
      <label>Email:</label>
      <input type="email" formControlName="email">
      @if (registroForm.get('datosPersonales.email')?.errors?.['email'] && registroForm.get('datosPersonales.email')?.touched) {
        <span class="error-msg">Formato de email inválido.</span>
      }
    </div>
  </fieldset>

  <!-- Grupo: Seguridad -->
  <fieldset formGroupName="seguridad">
    <legend>Seguridad</legend>
    
    <div class="form-group">
      <label>Contraseña:</label>
      <input type="password" formControlName="password">
    </div>

    <div class="form-group">
      <label>Confirmar Contraseña:</label>
      <input type="password" formControlName="confirmPassword">
    </div>

    <!-- Error cruzado -->
    @if (registroForm.get('seguridad')?.errors?.['mismatch'] && registroForm.get('seguridad')?.touched) {
      <span class="error-msg cross-error">Las contraseñas no coinciden.</span>
    }
  </fieldset>

  <!-- Arreglo: Habilidades Dinámicas -->
  <fieldset>
    <legend>Habilidades</legend>
    <div formArrayName="habilidades">
      @for (hab of habilidades.controls; track $index) {
        <div class="form-group dynamic-row">
          <input [formControlName]="$index" placeholder="Ej. Angular, Java...">
          <button type="button" class="btn-danger" (click)="removerHabilidad($index)">Remover</button>
        </div>
      }
    </div>
    <button type="button" class="btn-secondary" (click)="agregarHabilidad()">+ Agregar Habilidad</button>
  </fieldset>

  <!-- Submit -->
  <button type="submit" class="btn-primary" [disabled]="registroForm.invalid">Registrarse</button>
</form>
```

## 9. Conclusión

Los Formularios Reactivos ofrecen un poder inmenso para manejar requerimientos complejos de datos en aplicaciones de nivel empresarial. Al utilizar TypeScript para manejar el estado del formulario, aplicar validadores síncronos/asíncronos y cruzar validaciones, junto con la nueva API reactiva de Signals de Angular, obtenemos un código extremadamente limpio, testeable y robusto.
