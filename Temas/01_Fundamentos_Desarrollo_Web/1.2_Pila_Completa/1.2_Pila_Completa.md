# Tema 1.2: Enfoque de Desarrollo de Pila Completa (Full Stack Development)

## Resumen
En esta lectura usted estudiará el enfoque de desarrollo de pila completa (*Full Stack Development*), analizando las responsabilidades diferenciadas de las capas cliente (*Front-end*) y servidor (*Back-end*). Comprenderá cómo interactúan estas tecnologías a través de APIs de red y estudiará un ejemplo práctico de integración de ambas capas utilizando un servidor en **Java** y un cliente web en HTML5/JavaScript.

---

## Concepto Principal (El 'Qué')

El **desarrollo de pila completa (Full Stack Development)** se refiere a la creación integrada de todas las capas de una aplicación de software distribuida. En el desarrollo web moderno, esto implica el dominio y la implementación de dos entornos de ejecución e infraestructura independientes:

### 1.2.1 El Back-end (Capa de Servidor)
Es la capa lógica y de procesamiento de datos oculta al usuario. Se encarga de gestionar la infraestructura de datos y la seguridad.
* **Componentes Principales:**
  * **Capa de Persistencia (Base de Datos):** Motores relacionales (ej. PostgreSQL, SQL Server) o no relacionales que almacenan el estado del negocio.
  * **Lógica de Negocios (Servicios y Modelos):** Código que ejecuta reglas de cálculo, flujos de trabajo e integridad (ej. cálculos de matrícula, validaciones de saldo).
  * **Capa de Controladores (APIs):** Expone endpoints que reciben peticiones del cliente (usualmente en formato JSON) y coordinan las respuestas.
* **Tecnologías Comunes:** Java (Spring Boot), C# (.NET Core), Node.js.

### 1.2.2 El Front-end (Capa de Cliente)
Es la capa visual e interactiva con la que el usuario final interactúa de forma directa en su navegador o dispositivo móvil.
* **Componentes Principales:**
  * **Estructura y Maquetación:** Documentación semántica (HTML5) y diseño visual responsive (CSS3).
  * **Lógica de Interfaz y Enrutamiento:** Controla la interactividad gráfica, las animaciones, las validaciones de formularios y el enrutamiento interno de vistas mediante frameworks de cliente (ej. **Angular**).
  * **Consumo de Servicios:** Peticiones HTTP asíncronas para leer o enviar datos a la API del backend.

---

## Analogía (La Intuición)

Considere la infraestructura de un **teatro de ópera**:
* **El Escenario y Actores (Front-end):** Es lo que el público ve de forma directa. La escenografía (HTML/CSS), la actuación interactiva (JavaScript) y la coordinación del libreto (Angular) están diseñados exclusivamente para la experiencia y deleite del público.
* **Los Camerinos y Bastidores (Back-end):** Es el área oculta donde ocurre el trabajo operativo de soporte. Aquí se coordinan las luces, la tramoya, el control de accesos y la administración del teatro (bases de datos, lógica de negocio y seguridad).
* **El Director de Escena (API REST):** Es el canal de comunicación que da indicaciones en tiempo real a los actores en escena sobre lo que ocurre tras bambalinas, sincronizando ambas realidades sin que el público vea el backstage.

## Ejemplo de Código e Implementación (El 'Cómo')

Para experimentar un flujo integrado de **Pila Completa**, implementaremos un servidor backend minimalista en **Java** que expone una API de estudiantes y un cliente web en **HTML/JavaScript** que consume dicha API de forma asíncrona.

### Paso 1: El Servidor Back-end (Java)
Este programa escucha peticiones en el puerto `3000` y expone un endpoint `/api/estudiante` que retorna datos estructurados en formato JSON.

```java
import com.sun.net.httpserver.HttpServer;
import com.sun.net.httpserver.HttpHandler;
import com.sun.net.httpserver.HttpExchange;
import java.io.IOException;
import java.io.OutputStream;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;

public class BackendServer {
    public static void main(String[] args) throws IOException {
        int puerto = 3000;
        HttpServer server = HttpServer.create(new InetSocketAddress(puerto), 0);
        
        // Registrar endpoint de API
        server.createContext("/api/estudiante", new EstudianteHandler());
        
        server.setExecutor(null);
        System.out.println("Backend en Java escuchando en http://localhost:" + puerto);
        server.start();
    }

    static class EstudianteHandler implements HttpHandler {
        @Override
        public void handle(HttpExchange exchange) throws IOException {
            if ("GET".equalsIgnoreCase(exchange.getRequestMethod())) {
                // Habilitar encabezados CORS esenciales para el Front-end
                exchange.getResponseHeaders().set("Content-Type", "application/json; charset=utf-8");
                exchange.getResponseHeaders().set("Access-Control-Allow-Origin", "*");
                
                String JSON_PAYLOAD = "{"
                        + "\"carnet\": \"C01234\","
                        + "\"nombre\": \"Ana Pérez\","
                        + "\"carrera\": \"Informática Empresarial\","
                        + "\"sede\": \"Sede del Atlántico - Recinto Paraíso\""
                        + "}";
                
                byte[] responseBytes = JSON_PAYLOAD.getBytes(StandardCharsets.UTF_8);
                exchange.sendResponseHeaders(200, responseBytes.length);
                try (OutputStream os = exchange.getResponseBody()) {
                    os.write(responseBytes);
                }
            } else {
                exchange.sendResponseHeaders(405, -1);
            }
        }
    }
}
```

### Paso 2: El Cliente Front-end (HTML / JS)
Este archivo se ejecuta en el navegador web del usuario, consume de manera asíncrona el endpoint del servidor Java mediante la API nativa de JavaScript `fetch` e inyecta la información en el DOM.

```html
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Cliente Front-end UCR</title>
    <style>
        body { font-family: 'Segoe UI', sans-serif; background: #0f172a; color: #f8fafc; padding: 40px; text-align: center; }
        .card { background: #1e293b; padding: 25px; border-radius: 12px; display: inline-block; border: 1px solid #334155; max-width: 400px; }
        button { background: #0284c7; color: white; border: none; padding: 10px 20px; border-radius: 6px; cursor: pointer; font-weight: bold; }
        button:hover { background: #0369a1; }
        #resultado { margin-top: 20px; text-align: left; }
    </style>
</head>
<body>
    <div class="card">
        <h2>Pila Completa: Integración Client-Server</h2>
        <p>Haga clic para solicitar datos de matrícula al backend Java:</p>
        <button onclick="solicitarDatos()">Consultar Matrícula</button>
        <div id="resultado"></div>
    </div>

    <script>
        function solicitarDatos() {
            const apiUri = 'http://localhost:3000/api/estudiante';
            const contenedor = document.getElementById('resultado');
            
            contenedor.innerHTML = '<p>Cargando información del servidor...</p>';
            
            // Consumo asíncrono usando la API Fetch
            fetch(apiUri)
                .then(response => {
                    if (!response.ok) throw new Error('Error al conectar con la API');
                    return response.json();
                })
                .then(data => {
                    contenedor.innerHTML = `
                        <p><strong>Carnet:</strong> ${data.carnet}</p>
                        <p><strong>Estudiante:</strong> ${data.nombre}</p>
                        <p><strong>Carrera:</strong> ${data.carrera}</p>
                        <p><strong>Recinto:</strong> ${data.sede}</p>
                    `;
                })
                .catch(error => {
                    contenedor.innerHTML = `<p style="color: #f43f5e;"><strong>Fallo:</strong> ${error.message}</p>`;
                });
        }
    </script>
</body>
</html>
```

## Trampas Comunes (Gotchas)

1. **Duplicación de Validaciones (Validaciones Redundantes):** Es una trampa común asumir que si un formulario valida la entrada del usuario en el Front-end (ej. validar que un correo contenga `@` mediante JavaScript), el Back-end no requiere dicha validación. Recuerde: un atacante puede saltarse la UI y enviar peticiones maliciosas directamente al servidor. Las reglas de integridad crítica deben **validarse siempre en el Back-end**.
2. **Inconsistencia en el Formato de Datos (Contract Mismatches):** Cambiar un campo en el esquema del Back-end (ej. renombrar la variable `nombre` a `nombreCompleto` en el JSON) sin actualizar el modelo de recepción del Front-end romperá la visualización de la SPA y causará errores de consola silenciosos.
3. **Manejo Desordenado de Estados Asíncronos:** No mostrar pantallas o animaciones de carga (*Loaders*) mientras se procesa la petición de red asíncrona confunde al usuario, quien podría pulsar repetidamente el botón de acción enviando múltiples requests basura al servidor.
