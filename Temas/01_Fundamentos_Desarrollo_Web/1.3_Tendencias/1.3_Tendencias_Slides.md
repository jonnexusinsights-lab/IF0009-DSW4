## 1. Multi-Page Applications (MPA)

* Modelo tradicional guiado por el **servidor web**.
* Cada interacción o navegación del cliente requiere un **refresco completo** de página.
* El servidor procesa, consulta datos y devuelve un documento HTML completo.
* **Ventajas principales:**
  * <span class="highlight">SEO excelente e inmediato:</span> Todo el contenido se pre-renderiza en el backend.
  * Carga inicial reducida para dispositivos de bajas especificaciones.
* **Desventajas:** Mayor latencia y consumo ineficiente de ancho de banda.

---

## 2. Single-Page Applications (SPA)

* El navegador descarga un único archivo HTML base, CSS y un bundle de JavaScript (Angular).
* La navegación se maneja del **lado del cliente (Client-Side Routing)**.
* Se intercambian únicamente datos estructurados (**JSON**) mediante APIs RESTful.
* **Ventajas principales:**
  * <span class="highlight">Transiciones instantáneas:</span> Experiencia fluida sin parpadeos de pantalla.
  * Desacoplamiento limpio entre lógica de datos (Backend) y visualización (Frontend).
* **Desventajas:** Primer tiempo de carga lento y retos adicionales de indexación SEO.

---

## Comparación de Renderizado: MPA vs SPA

```text
MPA (Server-Side Rendering):
[Navegador] ────── GET /portal ──────> [Servidor Spring Boot]
[Navegador] <── HTML Renderizado ────── [Servidor Spring Boot]

SPA (Client-Side Rendering):
[Navegador] ────── GET /api/datos ────> [Servidor Spring Boot]
[Navegador] <── [JSON con Data] ─────── [Servidor Spring Boot]
                 (JavaScript en el navegador dibuja el HTML)
```

## 3. Progressive Web Applications (PWA)

* Aplicación web (típicamente SPA) que utiliza APIs modernas para imitar una app móvil nativa.
* **Pilares Tecnológicos:**
  * **Service Workers:** Scripts en segundo plano que manejan la red, caché y permiten el <span class="highlight">funcionamiento offline</span>.
  * **Web App Manifest:** Archivo JSON que describe propiedades visuales para instalar la app en el dispositivo.
* **Características:** Notificaciones push nativas, instalación directa y actualizaciones seguras en segundo plano.

---

## 4. Aplicaciones Nativas

* Aplicaciones móviles compiladas para un sistema operativo y arquitectura específicos.
* Escritas en el lenguaje oficial (Swift para iOS, Kotlin para Android) o frameworks multiplataforma (Flutter, React Native).
* **Ventajas:**
  * <span class="highlight">Rendimiento óptimo:</span> Acceso directo al hardware sin puentes ni navegadores intermediarios.
  * Acceso total a APIs internas (Bluetooth, sensores de precisión, contactos).
* **Desventajas:** Ciclos de desarrollo paralelos, distribución limitada a tiendas (App/Play Store) y actualizaciones lentas.

## Implementación de Controladores en Spring Boot (Java)

```java
@Controller
@RequestMapping("/noticias")
public class NoticiasController {

    // 1. APROXIMACIÓN MPA (Retorna una plantilla Thymeleaf renderizada en el backend)
    @GetMapping("/portal")
    public String verPortalNoticias(Model model) {
        model.addAttribute("noticias", servicio.obtenerNoticias());
        return "noticias_template"; // Busca noticias_template.html
    }

    // 2. APROXIMACIÓN SPA / API REST (Retorna datos en JSON crudo)
    @GetMapping("/api")
    @ResponseBody
    public List<Noticia> obtenerNoticiasJson() {
        return servicio.obtenerNoticias();
    }
}
```

## Trampas Comunes (Gotchas)

* **SPA e Indexación SEO:**
  * Los robots antiguos de indexación no ejecutan JavaScript. Si indexan su SPA, verán una página en blanco (`<app-root></app-root>`).
  * *Solución:* Implementar **Server-Side Rendering (SSR)** para la primera carga.
* **PWA y Caché del Service Worker:**
  * La caché persistente puede congelar la app en versiones viejas.
  * *Solución:* Usar hash unique de compilación para invalidar scripts viejos.
