# Tema 7.1.2: Servidores de Hosting Estático y Dinámico: Enrutamiento SPA, Servidores de Aplicaciones y Caché

> [!NOTE]
> Este documento corresponde a la lectura técnica del **Subtema 7.1.2**. En esta unidad usted analizará la distribución desacoplada de aplicaciones modernas, contrastando los **Servidores de Hosting Estático** para arquitecturas Single Page Application (**Angular 17+**) con los **Servidores de Hosting Dinámico y Servidores de Aplicaciones** para la capa de servicios en **Spring Boot 3 / Java 25**. Profundizaremos en la resolución del problema de enrutamiento SPA (reescritura hacia `index.html`) y políticas de almacenamiento en caché.

---

## 1. Resumen Ejecutivo

Una arquitectura web moderna de pila completa (*Full-Stack*) desacopla deliberadamente la entrega de los archivos de presentación estáticos (HTML, JavaScript, CSS, imágenes) del procesamiento transaccional de la lógica de negocio y base de datos. En esta lección, usted comprenderá cómo los servidores de hosting estático y redes de entrega de contenido (CDNs) permiten despachar la aplicación cliente con latencias mínimas a nivel global, cómo solucionar el clásico error HTTP 404 que sufren las SPAs al recargar rutas internas, y cómo alojar el backend dinámico de Spring Boot maximizando la concurrencia de peticiones.

### 2.1 El Problema Fundamental del Enrutamiento SPA (Client-Side Routing)
En una aplicación de páginas múltiples clásica (MPA), cada ruta como `/estudiantes` o `/cursos/10` corresponde a un archivo físico en el servidor o a una ruta controlada por el backend.
Por el contrario, en una **Single Page Application (Angular)**:
1. El servidor solo posee un único archivo HTML real: `index.html`.
2. Cuando el usuario navega a `/estudiantes`, el **enrutador de Angular** intercepta la acción mediante la API `window.history.pushState()` del navegador, actualizando la barra de direcciones y renderizando el componente en memoria sin enviar una petición al servidor.
3. **El Problema del Error 404:** Si el usuario presiona la tecla de recarga (F5) en `https://mi-dominio.com/estudiantes`, el navegador envía una petición `GET /estudiantes` al servidor de hosting. Como no existe ninguna carpeta o archivo físico llamado "estudiantes" en el disco, el servidor responde con un error `404 Not Found`.

**La Solución Universal (Fallback / URL Rewrite):**
El servidor de hosting debe configurarse para que cualquier petición que no coincida con un archivo estático existente (`.js`, `.css`, `.png`) sea redirigida internamente devolviendo `index.html` con un código HTTP `200 OK`, permitiendo que Angular tome el control y dibuje la ruta correspondiente.

## 3. Analogía Didáctica (La Intuición)

* **Hosting Estático (La Librería):** Imagine una biblioteca pública que distribuye catálogos impresos a los visitantes. La biblioteca no redacta libros en vivo cuando la gente entra; simplemente entrega folletos preimpresos que ya están guardados en estanterías (archivos estáticos minificados). La entrega es instantánea y económica.
* **Hosting Dinámico (La Notaría / Fábrica):** Es una oficina notarial donde cada trámite requiere revisar firmas, consultar bases de datos jurídicas y emitir escrituras personalizadas únicas para cada ciudadano (ejecución de código Java en Spring Boot, transacciones ACID).
* **El Enrutador SPA:** Imagine que usted lleva un mapa interactivo plegable dentro del folleto. Mientras camina por la biblioteca, usted decide ir a la "Sala de Historia". Si cierra los ojos y vuelve a abrir el folleto, el bibliotecario debe entregarle nuevamente el mapa general de bienvenida para que usted vuelva a ubicar la Sala de Historia en su recorrido personal.

## 4. Implementación Técnica (El "Cómo"): Reglas de Enrutamiento y Políticas de Caché

### 4.1 Configuración de Reescritura para SPAs en Apache HTTP Server (`.htaccess`)

Si se utiliza un servidor web convencional para alojar los archivos compilados de la carpeta `dist/`:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  # Si el recurso solicitado no es un archivo físico existente
  RewriteCond %{REQUEST_FILENAME} !-f
  # Y el recurso solicitado no es un directorio físico existente
  RewriteCond %{REQUEST_FILENAME} !-d
  # Redirige internamente a index.html para que Angular Router resuelva la vista
  RewriteRule ^(.*)$ /index.html [L]
</IfModule>
```

### 4.2 Estrategia de Almacenamiento en Caché HTTP Defensiva

Para garantizar que los usuarios reciban actualizaciones inmediatas sin sacrificar rendimiento:

| Tipo de Activo | Regla de Encabezado `Cache-Control` | Justificación Técnica |
| :--- | :--- | :--- |
| **`index.html`** | `no-cache, no-store, must-revalidate` | El navegador debe consultar siempre al servidor para saber si hay nuevos bundles hash. |
| **Archivos con Hash (`main.[hash].js`)** | `public, max-age=31536000, immutable` | El contenido nunca cambia. Se almacena en la caché del navegador durante 1 año. |
| **Recursos Gráficos (`logo.png`)** | `public, max-age=86400` | Caché moderada de 24 horas para imágenes estáticas. |

### 4.3 Servidor de Aplicaciones Dinámico: Spring Boot 3 con Tomcat Embebido

Spring Boot incorpora por defecto el contenedor **Apache Tomcat 10+** optimizado dentro del propio Fat JAR. Su comportamiento en producción se configura en `application.properties`:

```properties
# Configuración del servidor de aplicaciones embebido
server.port=8080
server.tomcat.threads.max=200
server.tomcat.threads.min-spare=20
server.tomcat.connection-timeout=20000
server.tomcat.max-connections=8192
server.tomcat.accept-count=100

# Compresión automática de respuestas HTTP (JSON grande)
server.compression.enabled=true
server.compression.mime-types=application/json,application/xml,text/html,text/xml
server.compression.min-response-size=2048
```

## 5. Trampas Comunes y Antipatrones

*   **Alojar el Frontend SPA y el Backend dentro del mismo proceso Java:** Incrustar la carpeta `dist/` de Angular dentro de `src/main/resources/static/` en Spring Boot. Esto acopla innecesariamente el ciclo de vida de despliegue: cada cambio cosmético de CSS obliga a recompilar y reiniciar el backend completo.
*   **Permitir que `index.html` se guarde en caché prolongada:** Configurar `Cache-Control: max-age=86400` en el archivo `index.html`. Cuando se publique una nueva versión con nuevos hashes, los clientes seguirán cargando el `index.html` antiguo apuntando a bundles que ya no existen en el servidor, provocando una pantalla en blanco.
*   **No habilitar compresión de respuestas:** Servir respuestas JSON pesadas sin compresión Gzip en Spring Boot, multiplicando innecesariamente el consumo de ancho de banda.
