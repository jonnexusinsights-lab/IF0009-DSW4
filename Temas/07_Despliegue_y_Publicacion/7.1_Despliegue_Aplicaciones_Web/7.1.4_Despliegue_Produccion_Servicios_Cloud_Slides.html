¿Por qué NUNCA usar nohup java -jar &?

  • Falta de Supervisión: Si la aplicación falla por OOM, no se reinicia.
  • Caídas por Reboot: Si el servidor se actualiza, la app no arranca sola.
  • Fuga de Logs: El archivo nohup.out crece indefinidamente hasta saturar el disco.
  • Riesgo de Seguridad: Suele ejecutarse con el usuario administrador por descuido.
  • Solución de Grado Empresarial: Integrar el proceso en systemd.

Unidad de Servicio systemd (api.service)

[Unit]
Description=API Spring Boot 3 (Java 25)
After=network.target

[Service]
User=appuser
WorkingDirectory=/var/www/api
ExecStart=/usr/bin/java -jar aplicacion.jar
EnvironmentFile=/etc/api/produccion.env
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
  • Garantiza reinicio en 5 segundos ante fallas y aislamiento con usuario sin privilegios.

Comandos de Operación del Administrador

  • Activar y Arrancar:
```bash sudo systemctl daemon-reload sudo systemctl enable --now api.service ```
  • Inspeccionar Estado:
```bash sudo systemctl status api.service ```
  • Logs en Vivo (Streaming):
```bash sudo journalctl -u api.service -f ```

Despliegue en Cloud PaaS (Azure, AWS, Render)

  • Modelo Administrado (Platform as a Service):
    • La infraestructura y el sistema operativo son gestionados por el proveedor de nube.
  • Ventajas:
    • Despliegue directo del archivo .jar sin configurar Linux manualmente.
    • Escalabilidad vertical y horizontal automática (Auto-scaling).
    • Monitoreo integrado de salud y balanceo de carga nativo.
