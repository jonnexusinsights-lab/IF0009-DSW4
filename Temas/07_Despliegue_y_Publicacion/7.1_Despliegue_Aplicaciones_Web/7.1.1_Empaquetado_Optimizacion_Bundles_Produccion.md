# Tema 7.1.1: Empaquetado y Optimización de Bundles para Producción: Angular 17+ y Spring Boot 3 en Java 25

> [!NOTE]
> Este documento corresponde a la lectura técnica del **Subtema 7.1.1**. En esta lección usted analizará los procesos de compilación, empaquetado y optimización de activos para entornos productivos. Estudiaremos la compilación **AOT (Ahead-Of-Time)**, *Tree Shaking* y *Cache Busting* en **Angular 17+**, así como la creación de artefactos JAR ejecutables independientes y la calibración de la JVM en **Spring Boot 3 con Java 25**.

---

## 1. Resumen Ejecutivo

El código desarrollado en un entorno local contiene comentarios, mapas de código fuente de depuración (*source maps*), dependencias de prueba y configuraciones permisivas no aptas para el consumo masivo en Internet. El paso a producción exige una transformación profunda orientada a minimizar la latencia de red, maximizar la tasa de transferencia y optimizar el consumo de CPU y memoria RAM. En este módulo, usted dominará las técnicas para generar *bundles* web ultraligeros y empaquetar aplicaciones de backend en ejecutables autónomos listos para alta disponibilidad.

### 2.1 Técnicas Fundamentales en el Frontend (Angular 17+)
* **Compilación AOT (Ahead-Of-Time):** Traduce las plantillas HTML y componentes de Angular a código JavaScript eficiente durante la fase de compilación, eliminando la necesidad de incluir el compilador de Angular dentro del bundle del navegador.
* **Tree Shaking (Eliminación de Código Muerto):** Los empaquetadores analizan estáticamente los árboles de importaciones `import { ... }` y descartan automáticamente cualquier función, clase o módulo que no sea invocado en ninguna parte de la aplicación.
* **Cache Busting:** Generación de nombres de archivo con huellas digitales criptográficas basadas en el contenido (`main.[hash].js`). Si el código cambia, el hash varía y el navegador se ve obligado a descargar la nueva versión; si el archivo no cambió, el navegador lo lee instantáneamente desde la memoria caché local (HTTP 304).
* **División de Código (Code Splitting & Lazy Loading):** Carga bajo demanda únicamente los módulos o componentes correspondientes a la ruta que el usuario está visitando, postergando la descarga de pantallas secundarias.

### 2.2 Optimización del Backend en Spring Boot 3 / Java 25
* **Fat JAR Autónomo:** Maven empaqueta el código compilado junto con todas sus dependencias transitivas y el servidor web embebido (Tomcat) en un único archivo ejecutable `.jar`, ejecutable con `java -jar`.
* **Perfiles de Producción (`prod`):** Deshabilitan consolas de desarrollo (ej. consola web de H2), eliminan logs de depuración verbose (`DEBUG` $\to$ `WARN`), y activan conexiones a bases de datos relacionales empresariales con pools de conexiones HikariCP dimensionados.

## 4. Implementación Técnica (El "Cómo"): Compilación y Parámetros de Ejecución

### 4.1 Compilación de Angular 17+ para Producción

En la raíz del proyecto Angular, ejecutamos:

```bash
# Compila con optimización máxima en la carpeta dist/
ng build --configuration production
```

En `angular.json`, la configuración de producción activa automáticamente:

```json
"configurations": {
  "production": {
    "optimization": true,
    "outputHashing": "all",
    "sourceMap": false,
    "namedChunks": false,
    "aot": true,
    "budgets": [
      {
        "type": "initial",
        "maximumWarning": "500kB",
        "maximumError": "1MB"
      }
    ]
  }
}
```

### 4.2 Empaquetado de Spring Boot 3 con Perfil de Producción (Java 25)

Empaquetamos el artefacto ejecutable mediante Maven:

```bash
# Limpia y empaqueta el Fat JAR excluyendo las pruebas de testeo
mvn clean package -DskipTests
```

Definimos `src/main/resources/application-prod.yml`:

```yaml
spring:
  config:
    activate:
      on-profile: prod
  datasource:
    url: ${DB_PROD_URL}
    username: ${DB_PROD_USER}
    password: ${DB_PROD_PASSWORD}
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
  jpa:
    show-sql: false # Deshabilita logs de consultas SQL en consola
    hibernate:
      ddl-auto: validate # Valida el esquema sin alterar tablas productivas

server:
  port: 8080
  error:
    include-message: never # Previene fugas de trazas de excepción
    include-stacktrace: never
```

### 4.3 Script de Ejecución con Calibración de la JVM (Java 25)

Para ejecutar el JAR en el servidor con gestión óptima de memoria:

```bash
java -server \
  -Xms512m \
  -Xmx2048m \
  -XX:+UseG1GC \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/var/log/app_oom.hprof \
  -Dspring.profiles.active=prod \
  -jar aplicacion-backend.jar
```

**Análisis de parámetros:**
* `-Xms512m`: Asigna 512 MB de memoria heap inicial para evitar pausas tempranas de redimensionamiento.
* `-Xmx2048m`: Fija un límite máximo estricto de 2 GB de memoria RAM para la JVM.
* `-XX:+UseG1GC`: Utiliza el recolector de basura de primera generación (*Garbage-First Garbage Collector*), optimizado para baja latencia.

## 5. Trampas Comunes y Antipatrones

*   **Desplegar con `sourceMap: true` en producción:** Dejar activos los mapas de código fuente en Angular. Cualquier usuario que abra las DevTools del navegador podrá leer el código TypeScript original sin minificar, incluyendo comentarios y nombres de funciones internas.
*   **Dejar `spring.jpa.hibernate.ddl-auto=update` en producción:** Permitir que Hibernate modifique automáticamente el esquema de tablas en caliente. Una mala interpretación de una relación `@OneToMany` puede causar bloqueos de tablas o pérdida de columnas con datos reales.
*   **Omitir límites de tamaño de bundles (*Budgets*):** No configurar advertencias de tamaño en Angular, permitiendo que librerías pesadas inflen el tamaño inicial a más de 5 MB, destruyendo la experiencia de carga en redes móviles lentas.
