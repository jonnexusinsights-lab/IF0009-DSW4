# El Problema de la Carga de Datos Masivos

* **In-Memory Pagination (Carga en Memoria):**
  * Traer miles de filas a la JVM y luego hacer `.subList(0, 10)` agota la memoria RAM y causa `OutOfMemoryError`.
* **Paginación en Base de Datos (Database-Level Pagination):**
  * El motor de base de datos corta y retorna únicamente las filas necesarias (`LIMIT / OFFSET`).
  * Minimiza el tráfico de red y reduce el consumo de CPU en el servidor Java.

# Mecánica SQL e Internals de Hibernate

* Hibernate traduce la configuración de paginación a sintaxis nativa según el dialéctico del motor:
  * **SQL Server:** `OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY`
  * **PostgreSQL / MySQL:** `LIMIT 10 OFFSET 20`
* **API nativa de Hibernate:**
  * `query.setFirstResult(20);` (desplazamiento u offset inicial)
  * `query.setMaxResults(10);` (límite o tamaño de página)

# Abstracciones Clave en Spring Data JPA

* **`Pageable`:** Interfaz de solicitud (`page`, `size`, `Sort`).
  * `PageRequest.of(0, 10, Sort.by("nombre").ascending())`
  * *Nota:* Los índices de página inician en **`0`**.
* **`Page<T>`:** Respuesta completa.
  * Contiene los datos de la página + ejecución de **`SELECT COUNT(*)`** para metadatos (`totalElements`, `totalPages`).
* **`Slice<T>`:** Respuesta ligera.
  * Indica solo si hay una página posterior (`hasNext()`) **sin ejecutar `COUNT(*)`**. Ideal para scroll infinito.

# Mapeo en Repositorios y Servicios

```java
@Repository
public interface ProductoRepository extends JpaRepository<Producto, Long> {

    // Paginación derivativa automática
    Page<Producto> findByCategoria(String categoria, Pageable pageable);

    // Optimización con Slice (Sin SELECT COUNT(*))
    Slice<Producto> findByNombreContaining(String termino, Pageable pageable);
}
```

```java
// En la capa de Servicio:
Pageable pageable = PageRequest.of(page, size, Sort.by(Sort.Direction.ASC, sortBy));
Page<Producto> entidades = productoRepository.findAll(pageable);
return entidades.map(p -> new ProductoDTO(p.getId(), p.getNombre(), p.getPrecio()));
```

# Exposición RESTful en el Controller

```java
@RestController
@RequestMapping("/api/v1/productos")
public class ProductoController {

    private final ProductoService productoService;

    public ProductoController(ProductoService productoService) {
        this.productoService = productoService;
    }

    @GetMapping
    public ResponseEntity<Page<ProductoDTO>> listar(
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "10") int size,
            @RequestParam(defaultValue = "id") String sortBy) {

        return ResponseEntity.ok(productoService.obtenerProductosPaginados(page, size, sortBy));
    }
}
```

# Advertencias y Trampas Comunes

* **`JOIN FETCH` con Colecciones `@OneToMany`:**
  * Causa la advertencia `HHH000104: firstResult/maxResults specified with collection fetch; applying in-memory!`.
  * *Solución:* Usar `@EntityGraph` o paginar en dos pasos.
* **Costo de `SELECT COUNT(*)`:**
  * En tablas de millones de registros el conteo es costoso. Usar `Slice<T>` si no se requiere el total de páginas en la UI.
* **Desfase de Índice 0 vs 1:**
  * `page = 0` es la primera página en Spring Boot; la UI debe ajustar el parámetro si expone índices base 1.
