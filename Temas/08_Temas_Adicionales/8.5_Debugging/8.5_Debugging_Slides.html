¿Qué es la Depuración (Debugging)?

  • Proceso sistemático de identificar, aislar y corregir fallas en el software.
  • Diferencia clave:
    • Pruebas (Testing): Detectan la presencia de un defecto.
    • Depuración (Debugging): Encuentra la causa raíz del defecto.
  • Dos aproximaciones metodológicas principales:
    • Análisis Estático: Inspección de código sin ejecutar (linters, compilador).
    • Análisis Dinámico: Monitoreo y control del programa en ejecución.

Conceptos Clave de Depuración Dinámica

  • Punto de Interrupción (Breakpoint):
    • Pausa la ejecución del programa antes de ejecutar una línea específica.
  • Pila de Llamadas (Call Stack):
    • Lista de métodos activos en ejecución en el hilo actual.
  • Watch (Inspección):
    • Monitoreo en tiempo real del valor de variables en memoria.

Comandos de Control de Flujo

  • Step Over (F10):
    • Ejecuta la línea actual y se detiene en la siguiente instrucción.
  • Step Into (F11):
    • Entra al detalle del método invocado en la línea actual.
  • Step Out (Shift + F11):
    • Completa el método actual y vuelve al llamador en la pila.

Configuración del Depurador (launch.json)

  • VS Code utiliza el archivo .vscode/launch.json para gestionar perfiles: 
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "java",
            "name": "Debug Java Server",
            "request": "launch",
            "mainClass": "cr.ac.ucr.paraiso...AppServer"
        }
    ]
}

Ejemplo de Código con Falla Común

public class CalculadoraSalarios {
    public static void main(String[] args) {
        List<Empleado> empleados = obtenerEmpleados();
        double total = 0;
        for (Empleado emp : empleados) {
            // Lanza NullPointerException si un elemento es null
            total += emp.getSalarioNeto();
        }
        System.out.println("Total: " + total);
    }
}
  • Colocar un Breakpoint en el bucle for permite examinar qué elemento de la lista causó el valor null.

Depuración en el Navegador (Chrome DevTools)

  • Acceso rápido en el navegador: presione F12 o Ctrl + Shift + I.
  • Pestaña Console (Consola):
    • Muestra excepciones de JavaScript en caliente.
    • Imprime logs generados con console.log().
    • Visualiza advertencias de recursos bloqueados por CORS o tipos MIME incorrectos.
  • Pestaña Sources (Orígenes):
    • Permite colocar breakpoints directamente en el código de JavaScript del cliente.
    • Inspecciona variables y la pila de ejecución en el navegador.

DevTools: Análisis de Red (Pestaña Network)

  • Esencial para diagnosticar la comunicación asíncrona entre Frontend y Backend.
  • Inspección de Encabezados (Headers):
    • Validar que Content-Type sea application/json en peticiones POST.
  • Inspección del Payload (Carga Útil):
    • Verificar que el JSON enviado por el cliente tenga el formato y claves correctas.
  • Inspección de la Respuesta (Response):
    • Analizar el código de estado (ej. 200 OK, 404, 415 o 500) y el JSON devuelto por el Backend.

Depuración Asistida con IA (Google Antigravity)

  • Utilizar prompts estructurados optimiza el diagnóstico de trazas complejas:
  • Análisis de excepciones:
    • "Asistente, analice el siguiente error [pegar error] y proponga posibles causas y correcciones."
  • Refactorización defensiva:
    • "Asistente, diseñe una corrección robusta contra NullPointerException en este método [pegar código]."

Trampas Comunes al Depurar

  • No recompilar previamente:
    • Ejecutar el debugger sin hacer un mvn compile previo causará que el IDE muestre desfases de línea.
  • Ingresar a librerías de terceros (JDK):
    • Presionar Step Into en métodos nativos (System.out.println) abrirá el fuente del JDK.
    • Use Step Out para salir rápidamente.
  • Puntos de interrupción grises:
    • Ocurre si la clase binaria no se compiló con metadata de depuración.
