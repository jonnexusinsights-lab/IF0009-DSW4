Mapeo de Relaciones Bidireccionales

  • Relaciones en JPA:
    • Unidireccional: Solo una clase conoce la relación (ej. Pelicula -> Genero).
    • Bidireccional: Ambas clases se conocen en memoria.
  • Propietario de la Relación:
    • La entidad con la clave foránea física (dueña) lleva la anotación @ManyToOne.
    • La entidad inversa mapea la relación con el atributo mappedBy.
  • orphanRemoval = true:
    • Elimina físicamente registros secundarios huérfanos al sacarlos de la lista.
    • Se combina con CascadeType.ALL para persistencia en cascada.

Consultas Personalizadas: JPQL vs SQL Nativo

  • Anotación @Query: Permite escribir consultas complejas fuera del estándar.
  • JPQL (Java Persistence Query Language):
    • Basado en el grafo de objetos Java (entidades y atributos).
    • Independiente del motor de base de datos (portabilidad de base de datos).
  • SQL Nativo (nativeQuery = true):
    • Sentencias SQL directas contra las tablas y columnas físicas.
    • Permite consumir optimizaciones específicas del motor (ej. SQL Server).

Operaciones de Modificación Masiva

  • Consultas de Actualización o Borrado Masivo (UPDATE / DELETE):
    • Se declaran con @Query y requieren obligatoriamente @Modifying.
    • Deben ejecutarse dentro de un límite transaccional @Transactional.
  • La Trampa de la Memoria Caché:
    • Las consultas masivas evaden el contexto de persistencia (L1 Cache).
    • Solución: Usar @Modifying(clearAutomatically = true) para limpiar RAM.

Auditoría Automática (Spring Data Auditing)

  • Rastreo Automático de Metadata:
    • Registro automatizado de fechas de creación y modificación de filas.
  • Anotaciones de Propiedad:
    • @CreatedDate: Registra la fecha y hora inicial de guardado.
    • @LastModifiedDate: Sobrescribe la fecha en actualizaciones.
  • Activación en Spring Boot:
    • @MappedSuperclass y @EntityListeners(AuditingEntityListener.class) en el padre.
    • @EnableJpaAuditing en una clase de configuración @Configuration.

Código: Relación Bidireccional (Pelicula.java)

@Entity
@Table(name = "Pelicula")
public class Pelicula extends AuditableEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    private String titulo;

    @OneToMany(mappedBy = "pelicula", cascade = CascadeType.ALL, 
               orphanRemoval = true, fetch = FetchType.LAZY)
    private List<Review> reviews = new ArrayList<>();

    // Helpers bidireccionales en memoria:
    public void addReview(Review review) {
        reviews.add(review);
        review.setPelicula(this);
    }
}

Código: Repositorio (JPQL, Nativo y Modifying)

@Repository
public interface PeliculaRepository extends JpaRepository<Pelicula, Integer> {
    // JPQL
    @Query("SELECT p FROM Pelicula p JOIN p.reviews r WHERE r.calificacion >= :score")
    List<Pelicula> buscarPeliculasConBuenasResenas(@Param("score") int score);

    // SQL Nativo
    @Query(value = "SELECT * FROM Pelicula p WHERE p.titulo LIKE %:keyword%", 
           nativeQuery = true)
    List<Pelicula> buscarPorTituloNativo(@Param("keyword") String keyword);

    // Modifying
    @Modifying(clearAutomatically = true)
    @Query("UPDATE Pelicula p SET p.titulo = UPPER(p.titulo) WHERE p.id = :id")
    int convertirTituloAMayusculas(@Param("id") Integer id);
}

Trampas Comunes en Persistencia Avanzada

  • Mapeo Bidireccional sin mappedBy:
    • Hibernate creará una tabla puente redundante degradando el rendimiento.
  • orphanRemoval sin Cascade:
    • Si saca un objeto de la lista e intenta salvar, Hibernate no propagará el borrado.
  • Evadir Caché L1 en @Modifying:
    • Modificaciones en base de datos que no se refrescan en los objetos en memoria RAM.
    • Solución: Usar siempre clearAutomatically = true.
