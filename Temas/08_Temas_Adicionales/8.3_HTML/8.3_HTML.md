# Tema 8.3: Web Components y APIs Modernas de HTML5

## Resumen
En esta lectura, usted estudiará los fundamentos de los **Web Components**, el estándar nativo del consorcio W3C para crear elementos HTML personalizados, reutilizables y encapsulados. Aprenderá a utilizar las APIs de **Custom Elements**, **Shadow DOM** y **HTML Templates**, así como a interactuar con los atributos de datos personalizados (`data-*` y la API `dataset`) para integrarlos con JavaScript y CSS en sus desarrollos de software.

---

## Concepto Principal (El 'Qué')

El estándar de **Web Components** permite extender las capacidades nativas del navegador mediante la definición de etiquetas personalizadas. A diferencia de componentes construidos en frameworks específicos (como Angular o React) que requieren compiladores y bibliotecas asociadas, los Web Components son interpretados directamente por el motor del navegador web de manera nativa.

Este estándar se fundamenta en tres pilares técnicos:

1. **Custom Elements (Elementos Personalizados):**
   Es un conjunto de APIs de JavaScript que le permite definir nuevas etiquetas HTML (ej. `<perfil-usuario>`) y asociarles un comportamiento lógico heredando de la clase base `HTMLElement`. Los nombres de estos elementos deben contener obligatoriamente un guion medio (`-`) para evitar colisiones con futuras etiquetas nativas de HTML.
   
2. **Shadow DOM (DOM en la Sombra):**
   Proporciona encapsulamiento completo para el marcado HTML y las reglas de estilos CSS del componente. El Shadow DOM separa el árbol de renderizado del componente del DOM principal de la página (llamado *Light DOM*). Esto significa que las reglas de CSS de la página principal no se filtrarán dentro de su Web Component, y los estilos definidos dentro del Shadow DOM no afectarán al resto de la página.
   
3. **HTML Templates (Plantillas HTML):**
   Representadas por las etiquetas `<template>` y `<slot>`. Permiten escribir fragmentos de marcado HTML que no se renderizan inmediatamente al cargar la página, sino que se clonan y activan dinámicamente mediante JavaScript. Los `<slot>` sirven como marcadores de posición (*placeholders*) para inyectar contenido dinámico desde el exterior.

```
Estructura de Encapsulamiento del Shadow DOM:
[ Document (DOM Principal) ]
        └── <mi-tarjeta> (Shadow Host - Elemento contenedor)
                 └── #shadow-root (Límite del encapsulamiento)
                          ├── <style> (Estilos aislados del exterior)
                          ├── <p> (Marcado HTML interno)
                          └── <slot> (Punto de inyección para el Light DOM)
```

### Atributos de Datos Personalizados (`data-*`)
Para pasar datos del HTML a JavaScript de forma estructurada sin romper los estándares de validación, HTML5 define los atributos `data-*`. Cualquier atributo que comience con `data-` es recolectado automáticamente por el navegador y expuesto en JavaScript mediante la propiedad `.dataset` en formato camelCase (ej. `data-user-id` se expone en JS como `.dataset.userId`).

## Analogía (La Intuición)

Considere a los Web Components como **electrodomésticos modulares de cocina**:
* **El Custom Element es el aparato físico externo (ej. un microondas):** Tiene un nombre específico y una carcasa estandarizada que se conecta a la red eléctrica común (el DOM principal).
* **El Shadow DOM representa el encapsulamiento interno del microondas:** Los cables, el magnetrón y el circuito interno están aislados de la cocina. Si usted pinta las paredes de su cocina de rojo (CSS global), el circuito interno del microondas no se altera; de igual forma, el calor que produce adentro no quema su cocina (los estilos locales están protegidos).
* **La Plantilla (`<template>`) es el manual de fabricación:** Describe cómo ensamblar la bandeja giratoria y el panel táctil cada vez que se produce una nueva unidad del aparato en la fábrica.
* **Los Atributos `data-*` son los botones físicos de configuración externa:** Permiten indicarle al microondas el tiempo de cocción (`data-tiempo="60"`) sin necesidad de abrir la carcasa ni reprogramar el motor de fábrica.

## Ejemplo de Código e Implementación (El 'Cómo')

A continuación se presenta la implementación de un Web Component nativo que crea una tarjeta de usuario interactiva y encapsulada:

```html
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <title>Demostración de Web Components Nativa</title>
    <!-- Estilo global que intentará pintar los elementos 'span' de rojo -->
    <style>
        span {
            color: red;
            font-weight: bold;
        }
    </style>
</head>
<body>

    <h1>Visualización de Tarjetas</h1>

    <!-- Uso del Custom Element declarativo con atributos 'data-*' -->
    <tarjeta-contacto data-rol="Administrador">
        <span slot="nombre">Ing. Sofía Brenes</span>
    </tarjeta-contacto>

    <!-- Plantilla reutilizable -->
    <template id="plantilla-tarjeta">
        <style>
            /* Estos estilos aplican EXCLUSIVAMENTE dentro del Shadow DOM */
            .tarjeta {
                font-family: Arial, sans-serif;
                background-color: #f1f5f9;
                border-left: 5px solid #3b82f6;
                padding: 15px;
                margin: 10px 0;
                border-radius: 4px;
                max-width: 300px;
            }
            .rol {
                font-size: 0.85em;
                color: #64748b;
                text-transform: uppercase;
                letter-spacing: 1px;
            }
            /* Este span NO se pintará de rojo porque está aislado por el Shadow DOM */
            span {
                color: #1e293b;
                font-size: 1.1em;
            }
        </style>
        <div class="tarjeta">
            <div class="rol" id="etiqueta-rol">Usuario</div>
            <!-- Slot para recibir el nombre del Light DOM -->
            <slot name="nombre">Nombre por defecto</slot>
        </div>
    </template>

    <script>
        // Definición de la lógica del Custom Element
        class TarjetaContacto extends HTMLElement {
            constructor() {
                super();
                // 1. Crear el Shadow Root en modo abierto (open) para permitir depuración
                this.attachShadow({ mode: 'open' });

                // 2. Obtener y clonar la plantilla HTML
                const plantilla = document.getElementById('plantilla-tarjeta');
                const contenidoClonado = plantilla.content.cloneNode(true);

                // 3. Adjuntar el fragmento clonado al Shadow DOM
                this.shadowRoot.appendChild(contenidoClonado);
            }

            // Callback del ciclo de vida: Ejecutado cuando el elemento se inserta en el DOM
            connectedCallback() {
                // Leer el valor del atributo de datos 'data-rol' utilizando dataset
                const rol = this.dataset.rol || 'Invitado';
                
                // Modificar el elemento correspondiente en el Shadow DOM
                const contenedorRol = this.shadowRoot.getElementById('etiqueta-rol');
                contenedorRol.textContent = rol;
            }
        }

        // Registrar el nuevo elemento en el navegador web
        customElements.define('tarjeta-contacto', TarjetaContacto);
    </script>
</body>
</html>
```

### Explicación Línea por Línea
* **`class TarjetaContacto extends HTMLElement`**: Se crea la clase de control heredando de la clase base del DOM de HTML.
* **`this.attachShadow({ mode: 'open' })`**: Inicializa el aislamiento de estilos y marcado, permitiendo el acceso al árbol del componente a través de la propiedad `this.shadowRoot` de JavaScript.
* **`plantilla.content.cloneNode(true)`**: Realiza una copia profunda de la plantilla. Esto asegura eficiencia en memoria, ya que la plantilla se define una sola vez en el HTML y se duplica para cada instancia.
* **`this.dataset.rol`**: Accede de forma segura al atributo de datos `data-rol="Administrador"` declarado en la etiqueta del HTML.
* **`customElements.define('tarjeta-contacto', TarjetaContacto)`**: Vincula de manera formal la clase de lógica a la etiqueta de marcado personalizada dentro del motor del navegador.

## Trampas Comunes (Gotchas)

1. **Uso de Etiquetas Autocerrables:** 
   El parser de HTML no admite que los Custom Elements utilicen la sintaxis autocerrable (ej. `<tarjeta-contacto />`). Si usted lo escribe de esa forma, el navegador interpretará que el elemento permanece abierto y anidará todo el contenido subsiguiente dentro del componente, rompiendo la estructura de la página.
   * *Solución:* Utilice siempre etiquetas de apertura y cierre explícitas: `<tarjeta-contacto></tarjeta-contacto>`.

2. **Invisibilidad para Buscadores y Lectores de Pantalla (SEO y Accesibilidad):**
   El contenido encerrado de manera profunda en el Shadow DOM puede no ser analizado de forma óptima por indexadores web simples, y los lectores de pantalla a veces tienen problemas para navegar por árboles de Shadow DOM muy complejos si no se usan atributos WAI-ARIA explícitos.
   * *Solución:* Utilice los `<slot>` para mantener el contenido textual importante en el *Light DOM* principal (que es totalmente accesible) y use el Shadow DOM únicamente para la decoración, estructura visual e interactividad de estilos.
