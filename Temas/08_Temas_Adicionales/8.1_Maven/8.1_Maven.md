# Tema 8.1: Introducción a Maven — Gestión de Ciclo de Vida y Dependencias

## Resumen
En esta lectura, usted estudiará los fundamentos de **Apache Maven**, la herramienta estándar de la industria para la gestión de dependencias y automatización de la compilación en proyectos basados en la plataforma Java. Aprenderá a configurar la herramienta e integrar su flujo de desarrollo tanto en **Visual Studio Code** como en la plataforma asistida por inteligencia artificial **Google Antigravity**, comprendiendo la estructura jerárquica del archivo `pom.xml` y los ciclos de vida de compilación.

---

## Concepto Principal (El 'Qué')

**Apache Maven** es una herramienta declarativa de gestión de proyectos de software y comprensión de compilaciones. A diferencia de las herramientas imperativas tradicionales (como Apache Ant, donde se debe programar detalladamente cada tarea de copia y compilación), Maven opera bajo el paradigma de **Convención sobre Configuración** (*Convention over Configuration*). Esto significa que prescribe una estructura estándar de directorios y un ciclo de vida de compilación predefinido, requiriendo intervención de configuración solo cuando el proyecto se desvía de los valores predeterminados.

### El Archivo de Configuración Central: POM
El núcleo de todo proyecto Maven es el archivo **POM** (*Project Object Model*), plasmado en el archivo físico `pom.xml`. Este documento estructurado en formato XML contiene toda la metadata necesaria para describir el proyecto:
1. **Coordenadas del Proyecto (GAV):**
   * **`groupId`**: Identificador de la organización o grupo (ej. `cr.ac.ucr`).
   * **`artifactId`**: Nombre único del entregable o módulo del proyecto (ej. `sistema-transacciones`).
   * **`version`**: Versión del software, siguiendo convenciones como el versionado semántico o sufijos como `SNAPSHOT` para versiones en desarrollo.
2. **Gestión de Dependencias:** Declaración formal de bibliotecas externas requeridas. Maven descarga automáticamente estas dependencias y sus respectivas dependencias transitivas desde el repositorio global **Maven Central**, almacenándolas en el caché local del desarrollador (directorio `.m2`).
3. **Plugins y Propiedades:** Permite extender la funcionalidad del ciclo de compilación (ej. compilar con una versión específica de JDK, empaquetar en un archivo JAR gordo con dependencias, o generar reportes de pruebas).

```
Estructura de Directorios Estándar de Maven:
mi-proyecto/
├── pom.xml
└── src/
    ├── main/
    │   ├── java/         <-- Código fuente de producción Java
    │   └── resources/    <-- Archivos de configuración y propiedades
    └── test/
        ├── java/         <-- Código fuente de pruebas unitarias
        └── resources/    <-- Recursos exclusivos para pruebas
```

### Ciclos de Vida y Fases de Construcción
Maven organiza el proceso de compilación en tres ciclos de vida predefinidos: **default** (maneja la construcción y despliegue), **clean** (limpieza del directorio de trabajo) y **site** (generación de documentación). 

Cada ciclo de vida está compuesto por una secuencia ordenada de **fases**:
* **`validate`**: Verifica que el proyecto esté correcto y que toda la información necesaria esté disponible.
* **`compile`**: Compila el código fuente del proyecto (`.java` a `.class`) y lo coloca en el directorio `target/classes`.
* **`test`**: Ejecuta las pruebas unitarias usando frameworks como JUnit.
* **`package`**: Toma el código compilado y lo empaqueta en su formato de distribución (ej. archivo `.jar` o `.war`).
* **`install`**: Instala el paquete generado en el repositorio local `.m2` para que pueda usarse como dependencia en otros proyectos locales.
* **`deploy`**: Copia el paquete final a un repositorio remoto compartido para distribución.

*Regla clave:* Al ejecutar una fase específica en la terminal (ej. `mvn package`), Maven ejecuta automáticamente **todas las fases anteriores** de la secuencia en orden.

## Analogía (La Intuición)

Considere a Maven como un **asistente de cocina profesional y robotizado** en un restaurante de alta cocina:
* **El archivo `pom.xml` es la ficha técnica del platillo:** Detalla los ingredientes necesarios (dependencias), los utensilios especiales que se requieren (plugins) y el nombre oficial del plato (coordenadas del proyecto).
* **El repositorio Maven Central es el supermercado mayorista:** Si al asistente le falta un ingrediente (una biblioteca externa como Gson), él mismo viaja al supermercado, lo compra y lo almacena en la despensa de la cocina (repositorio local `.m2`) para no tener que volver a viajar la próxima vez que cocine el mismo plato.
* **El ciclo de compilación representa las etapas de preparación:** Desde la desinfección de la mesa (fase `clean`), cortar los ingredientes (fase `compile`), probar el sabor (fase `test`), hasta el emplatado final listo para el cliente (fase `package`).

## Ejemplo de Código e Implementación (El 'Cómo')

A continuación se presenta un archivo de configuración `pom.xml` básico que declara dependencias comunes para el procesamiento JSON y pruebas unitarias:

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    
    <modelVersion>4.0.0</modelVersion>

    <!-- Coordenadas del Proyecto (GAV) -->
    <groupId>cr.ac.ucr.if0009</groupId>
    <artifactId>modulo-adicional-maven</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <packaging>jar</packaging>

    <properties>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <!-- Declaración de Dependencias Externas -->
    <dependencies>
        <!-- Procesamiento de JSON (Gson) -->
        <dependency>
            <groupId>com.google.code.gson</groupId>
            <artifactId>gson</artifactId>
            <version>2.10.1</version>
        </dependency>

        <!-- Framework de Pruebas Unitarias (JUnit Jupiter) -->
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter-api</artifactId>
            <version>5.10.0</version>
            <scope>test</scope> <!-- Disponible solo durante la fase de prueba -->
        </dependency>
    </dependencies>
</project>
```

### Integración en Herramientas de Desarrollo

#### 1. Uso de Maven en Visual Studio Code (VS Code)
Para desarrollar proyectos Java administrados por Maven en VS Code, usted debe seguir este flujo de preparación:
- [ ] **Instalar la extensión oficial:** Instale el paquete de extensiones **Extension Pack for Java** (desarrollado por Microsoft), el cual incluye soporte nativo para proyectos Java, y la extensión **Maven for Java**.
- [ ] **Importar el proyecto:** Abra la carpeta raíz que contiene el archivo `pom.xml`. VS Code detectará el archivo de forma automática, activando el plugin de Java para descargar las dependencias declaradas y configurar el classpath del proyecto.
- [ ] **Ejecutar comandos mediante interfaz gráfica:** En la barra lateral izquierda, expanda la sección **MAVEN**. Desde allí, puede hacer clic derecho en el nombre de su proyecto y ejecutar fases comunes (`clean`, `compile`, `test`, `package`) sin necesidad de recordar la sintaxis de consola.

#### 2. Uso en el entorno Google Antigravity (AI Agent)
El asistente de desarrollo basado en IA **Google Antigravity** interactúa directamente con el SDK de Maven instalado en su sistema.
- [ ] **Solicitar asistencia de dependencias:** Usted puede solicitarle a la IA a través del chat: *"Agregue la última dependencia estable de Spring Boot Web al pom.xml"* o *"Configure la versión 17 de Java en las propiedades del compilador"*. La IA analizará la sintaxis correcta del XML y modificará el archivo respetando la estructura existente.
- [ ] **Ejecución y depuración autónoma:** Cuando usted le pide a Google Antigravity que verifique o construya su proyecto, este ejecutará comandos como `mvn clean test` tras bambalinas. Si el compilador de Java o las pruebas unitarias fallan, la IA leerá los logs de error de Maven y propondrá refactorizaciones automáticas en el código fuente para resolver las fallas.

## Trampas Comunes (Gotchas)

1. **El "Infierno de Dependencias" (Dependency Hell):** Si usted importa dos bibliotecas diferentes que a su vez requieren versiones distintas de una misma tercera biblioteca, Maven resolverá el conflicto automáticamente importando la versión que esté más cerca del nodo raíz en el árbol de dependencias. Esto puede provocar errores de compilación del tipo `NoSuchMethodError` en tiempo de ejecución.
   * *Solución:* Utilice el comando `mvn dependency:tree` en la terminal para inspeccionar el árbol jerárquico de importaciones y excluir dependencias conflictivas usando la etiqueta `<exclusions>`.
2. **Caché Corrupto en el Repositorio Local (`.m2`):** A veces, una descarga de dependencia se interrumpe (debido a fallas de conexión), dejando un archivo `.jar` corrupto o incompleto. Al compilar, Maven fallará indicando que no puede leer el paquete o la metadata.
   * *Solución:* Elimine la carpeta específica del paquete problemático dentro del directorio `~/.m2/repository/` y vuelva a compilar usando la bandera de actualización de snapshots: `mvn clean compile -U`.
