# ¿Por qué un Top 10 exclusivo para APIs?

* Las APIs REST no devuelven HTML decorado; exponen **datos y lógica pura** en JSON.
* **Superficie de Ataque Diferenciada:**
  * Exposición de identificadores primarios directamente en rutas REST.
  * Consumo desacoplado desde clientes móviles, web y servicios IoT.
  * Dificultad para auditar endpoints "invisibles" o no documentados (*Shadow APIs*).

---

# API1:2023 - Broken Object Level Auth (BOLA)

* **El Riesgo #1 Global en APIs:**
  * El atacante manipula el identificador en la URL:
    `/api/v1/recibos/1001` $\longrightarrow$ `/api/v1/recibos/1002`.
* **Causa Raíz:**
  * El backend valida que el token sea legítimo, pero **no comprueba la propiedad del objeto**.
* **Remediación Obligatoria:**
  * Regla contextual en servicio: `if (recibo.getUsuarioId() != token.getId()) throw Forbidden`.

---

# API3:2023 - Mass Assignment (BOPLA)

* **Mecánica de Vulnerabilidad:**
  * Ocurre al vincular directamente la entrada JSON con entidades de persistencia:
  ```json
  { "nombre": "Ana", "roles": ["ADMIN"] }
  ```
* Si la entidad JPA contiene `roles`, el atacante se autoasigna privilegios.
* **Defensa:** Usar siempre DTOs inmutables estrictos que solo admitan campos permitidos.

---

# API4:2023 - Unrestricted Resource Consumption

* Falta de límites en peticiones y consultas a bases de datos:
  * Cliente solicita `GET /api/logs?size=10000000`.
  * La JVM agota su memoria RAM (*OutOfMemoryError*) generando DoS.
* **Solución Defensiva:**
  * Paginación obligatoria con cota superior fija:
  ```java
  int tamanio = Math.min(size, 50); // Máximo 50 elementos
  ```
