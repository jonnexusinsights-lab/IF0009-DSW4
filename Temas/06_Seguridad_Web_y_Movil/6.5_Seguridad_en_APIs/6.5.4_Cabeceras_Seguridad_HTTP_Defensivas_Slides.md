# Objetivos de la Sesión

---

# `X-Content-Type-Options: nosniff`

* **El Problema:**
  * Navegadores antiguos intentaban adivinar el contenido (*MIME-Sniffing*).
  * Un archivo `.jpg` con código JavaScript malicioso era ejecutado como script.
* **La Solución:**
  * `nosniff` obliga al navegador a respetar estrictamente el `Content-Type`.
  * Si el servidor declara `image/jpeg`, el navegador **jamás lo ejecutará** como script.

---

# Clickjacking y `X-Frame-Options`

* **Mecánica del Ataque:**
  * Un sitio web malicioso incrusta su página en un `<iframe>` invisible (opacidad 0).
  * Coloca botones falsos encima para que la víctima haga clic involuntariamente.
* **Directiva Defensiva:**
  * `X-Frame-Options: DENY` (prohíbe que cualquier sitio lo incruste en frames).
  * `frame-ancestors 'none'` en CSP.

---

# Privacidad de Enlaces con `Referrer-Policy`

```http
Referrer-Policy: strict-origin-when-cross-origin
```

* **Comportamiento:**
  * Dentro del mismo origen: envía la ruta completa (`/perfil/juan/expediente`).
  * Hacia dominios externos: envía **únicamente el dominio** (`https://ucr.ac.cr`).
* Impide la filtración de tokens, IDs y parámetros privados en logs de terceros.

---

# Configuración en Spring Security 6 (Java 25)

```java
@Bean
public SecurityFilterChain securityHeaders(HttpSecurity http) throws Exception {
    return http
        .headers(h -> h
            .contentTypeOptions(Customizer.withDefaults())
            .frameOptions(f -> f.deny())
            .httpStrictTransportSecurity(hsts -> hsts.maxAgeInSeconds(31536000))
            .referrerPolicy(r -> r.policy(
                ReferrerPolicy.STRICT_ORIGIN_WHEN_CROSS_ORIGIN))
        )
        .build();
}
```

* Cumplimiento con grado "A+" en escaneos de SSL Labs y SecurityHeaders.
