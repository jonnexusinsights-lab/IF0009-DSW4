# ¿Qué es un "Origen" en la Web?

* Un origen está compuesto exactamente por:
  $$\text{Protocolo (http/https)} + \text{Dominio (host)} + \text{Puerto}$$
* **Ejemplo Práctico:**
  * Frontend Angular: `http://localhost:4200`
  * Backend Spring Boot: `http://localhost:8080`
  * Los puertos son distintos $\implies$ ¡Diferente origen!
* El navegador bloquea la lectura de la respuesta a menos que exista autorización CORS.

---

# Peticiones Preflight (`OPTIONS`)

* El navegador envía automáticamente una petición preliminar `OPTIONS` cuando:
  * El verbo es `PUT`, `DELETE` o `PATCH`.
  * La petición incluye cabeceras personalizadas (`Authorization`).
  * El `Content-Type` es `application/json`.
* **Respuesta Esperada del Servidor:**
  * Cabeceras `Access-Control-Allow-Origin` y métodos permitidos.
  * Código HTTP `204 No Content` o `200 OK`.

# Configuración Centralizada en Spring Boot 3

```java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("https://portal.ucr.ac.cr"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
    config.setAllowedHeaders(List.of("Authorization", "Content-Type"));
    config.setAllowCredentials(true);
    config.setMaxAge(3600L); // 1 hora de caché

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/api/**", config);
    return source;
}
```

* Política estricta que rechaza dominios no autorizados.

# Errores Comunes sobre CORS

* **"CORS protege mi backend de ataques":** FALSO. CORS solo es respetado por navegadores web; herramientas como cURL, Postman o scripts de atacantes lo ignoran por completo.
* **Usar `*` en producción:** Abrir la API a cualquier sitio web del mundo.
* **Combinar `*` con `AllowCredentials: true`:** Los navegadores modernos bloquean esta combinación inmediatamente arrojando error en consola.
