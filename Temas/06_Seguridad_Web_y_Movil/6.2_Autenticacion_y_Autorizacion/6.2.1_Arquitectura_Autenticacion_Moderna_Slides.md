# Stateful vs. Stateless: El Gran Dilema

* **Sesiones Tradicionales (Stateful):**
  * Servidor almacena el estado en memoria o base de datos en caché (Redis).
  * Cliente recibe identificador opaco (`JSESSIONID` en cookie HttpOnly).
  * Ventaja: Revocación instantánea.
  * Desventaja: Complejidad para escalar horizontalmente y soportar apps móviles.
* **Tokens Criptográficos (Stateless):**
  * Servidor no guarda estado; firma un token criptográfico portátil.
  * El token viaja en la cabecera `Authorization: Bearer <token>`.
  * Ventaja: Escalabilidad infinita y desacoplamiento total.

---

# Factores de Autenticación (MFA)

* El estándar exige combinar al menos dos categorías independientes:
  * **1. Algo que sabe:** Contraseña o PIN secreto.
  * **2. Algo que tiene:** Smartphone con app TOTP o llave física FIDO2.
  * **3. Algo que es:** Huella digital o escaneo facial biométrico.
* **Por qué depreciar SMS:**
  * Vulnerable a ataques de intercambio de SIM (*SIM Swapping*).
  * Interceptación en redes de telecomunicaciones (vulnerabilidades SS7).

---

# Funcionamiento Interno de TOTP (RFC 6238)

* Genera códigos de 6 dígitos que cambian cada 30 segundos.
* Combina una clave secreta compartida en Base32 con el tiempo Unix:
  $$\text{Paso} = \lfloor \text{Tiempo Actual} / 30 \rfloor$$
* Aplica `HMAC-SHA1(Clave, Paso)` y extrae 6 dígitos mediante truncamiento dinámico.
* **Tolerancia a Desfase:** El servidor debe validar ventanas $[-1, 0, +1]$ para mitigar diferencias de reloj.

# Biometría en Flutter 3 (`local_auth`)

```dart
final LocalAuthentication auth = LocalAuthentication();

bool puedeAutenticar = await auth.canCheckBiometrics;
if (puedeAutenticar) {
  bool exito = await auth.authenticate(
    localizedReason: 'Identifíquese para desbloquear su sesión',
    options: const AuthenticationOptions(
      biometricOnly: true,
      stickyAuth: true,
    ),
  );
}
```

# Buenas Prácticas Fundamentales

* **Desacople Biometría de la API:** La biometría móvil valida la presencia del usuario para desencriptar el token del Keystore; la API nunca debe recibir un simple booleano `"biometria_exitosa=true"`.
* **Cifrado de Secretos TOTP:** En la base de datos, el secreto Base32 debe guardarse cifrado con **AES-256-GCM**.
* **Tiempos de Vida Cortos:** Limitar la vigencia de tokens de acceso para reducir ventanas de riesgo.
