Anatomía de un JSON Web Token (RFC 7519)

  • Tres componentes Base64URL separados por puntos:
    • HEADER: Metadatos del algoritmo y tipo ({"alg":"HS256","typ":"JWT"}).
    • PAYLOAD: Reclamos (Claims) de usuario y sesión (sub, roles, exp).
    • SIGNATURE: Firma criptográfica que garantiza integridad inmutable.
  • Importante: El payload es legible en texto plano por cualquiera. Nunca guarde datos confidenciales sin cifrar (JWE).

Ataques Comunes contra JWT

  • 1. Ataque de Algoritmo Nulo (alg: none):
    • El atacante envía {"alg":"none"} y elimina la firma.
    • Si el parser no lo prohíbe explícitamente, valida el token modificado.
  • 2. Confusión de Claves (HMAC vs. RSA):
    • El atacante toma la clave pública RSA del servidor y la usa como secreto simétrico HMAC.
  • 3. Falta de Validación de Reclamos Estándar:
    • Omitir comprobación de expiración (exp), emisor (iss) o audiencia (aud).

Implementación Segura en Java 25 (JJWT)

// Forzar explícitamente el algoritmo en la firma
public String emitirToken(String usuarioId, List<String> roles) {
    return Jwts.builder()
        .subject(usuarioId)
        .claim("roles", roles)
        .issuer("UCR-IF0009")
        .expiration(Date.from(Instant.now().plus(15, ChronoUnit.MINUTES)))
        .signWith(claveSecreta, Jwts.SIG.HS256)
        .compact();
}
  • Rechaza dinámicamente cualquier intento de alterar el encabezado alg.

Patrón de Doble Token con Rotación

  • Access Token (Corta Duración: 15 min):
    • Se almacena en memoria de la app. Si es sustraído, expira pronto.
  • Refresh Token (Larga Duración: 7-30 días):
    • Se almacena cifrado en hardware nativo (Keystore/Keychain).
    • Solo se envía al endpoint /auth/refresh para renovar la sesión.
  • Detección de Reutilización:
    • Cada Refresh Token solo puede usarse una única vez.
    • Si el servidor detecta que un token ya usado vuelve a enviarse, asume un robo y revoca toda la sesión.

Buenas Prácticas de Hardening

  • Validar siempre la firma usando una clave de al menos 256 bits de entropía.
  • Descartar tokens con desfase de expiración excesivo (Clock Skew estricto).
  • No confiar en validaciones del lado del cliente en Angular o Flutter.
  • Restringir el emisor (iss) y la audiencia (aud) esperados en el parser.
