Los Cuatro Roles de OAuth 2.0

  • Resource Owner: El usuario propietario de la información.
  • Client: La aplicación que solicita actuar en representación del usuario (Flutter / Angular).
  • Authorization Server: Autentica al usuario, solicita consentimiento y emite tokens (Keycloak, Auth0).
  • Resource Server: La API RESTful protegida (Spring Boot 3) que valida los tokens y despacha datos.

¿Qué es PKCE y por qué es obligatorio?

  • Proof Key for Code Exchange (RFC 7636):
    • Diseñado específicamente para Clientes Públicos (Móviles y SPAs).
    • Los clientes públicos no pueden resguardar un client_secret de forma segura.
  • Mecánica del Desafío:
    • 1. Cliente genera code_verifier (cadena aleatoria).
    • 2. Calcula code_challenge = Base64URL(SHA-256(verifier)).
    • 3. Envía challenge en la petición de login.
    • 4. Al recibir el código temporal, lo canjea enviando el verifier original.
    • Neutraliza el robo de códigos de autorización en Deep Links.

OpenID Connect (OIDC): Identidad sobre OAuth 2.0

  • OAuth 2.0 es Autorización (permisos); OIDC es Autenticación (identidad).
  • Diferencia entre Tokens:
    • access_token: Diseñado para la API backend. Define scopes y accesos. Cadena opaca para el cliente.
    • id_token: Diseñado para el cliente móvil/web. JWT firmado con datos de perfil (sub, name, email).
  • Endpoint /userinfo: Consulta estandarizada de reclamos de identidad.

Resource Server en Spring Boot 3 (Java 25)

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) 
            throws Exception {
        return http
            .sessionManagement(s -> 
                s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/publico/**").permitAll()
                .anyRequest().authenticated()
            )
            .oauth2ResourceServer(oauth -> oauth.jwt(Customizer.withDefaults()))
            .build();
    }
}
  • Valida automáticamente la firma con la clave pública del Authorization Server.

Trampas de Seguridad en Clientes Públicos

  • Quemar el client_secret: Descompilar un .apk o abrir la pestaña Sources del navegador permite sustraerlo inmediatamente.
  • Omitir el parámetro state: Permite ataques de CSRF en el flujo de inicio de sesión.
  • No validar la audiencia (aud): Aceptar tokens emitidos para otra aplicación distinta dentro del mismo servidor de autenticación.
