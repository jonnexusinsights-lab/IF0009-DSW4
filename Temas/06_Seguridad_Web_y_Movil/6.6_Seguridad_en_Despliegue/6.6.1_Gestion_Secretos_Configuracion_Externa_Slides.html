Factor III: Configuración en el Entorno

  • Regla Fundamental:
    • El código fuente debe ser completamente agnóstico al entorno.
    • Si el código fuera liberado a la comunidad, no debe exponerse ninguna credencial.
  • Almacenamiento Seguro:
    • Variables de entorno en contenedores.
    • Bóvedas de secretos: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault.
    • Inyección en tiempo de ejecución (Runtime Injection).

Peligro de Git: La Inmutabilidad del Historial

  • Si un secreto se confirma en un commit:
    • Hacer un nuevo commit para borrarlo no lo elimina del historial.
    • Cualquier persona o bot puede inspeccionar git log -p y extraer la clave.
  • Respuesta de Incidente:
    • Paso 1: Rotar y revocar la clave en el proveedor de inmediato.
    • Paso 2: Purgar el commit con herramientas de reescritura (git-filter-repo).

Detección Automatizada con GitLeaks

# Escaneo de archivos preparados antes del commit
gitleaks protect --verbose --staged
  • Analiza entropía de cadenas y patrones de claves criptográficas conocidas.
  • Bloquea el commit localmente mediante hooks de Git antes de que llegue al servidor remoto.

Configuración Dinámica en Spring Boot 3

spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL}
    username: ${SPRING_DATASOURCE_USERNAME}
    password: ${SPRING_DATASOURCE_PASSWORD} # Falla si no se inyecta

app:
  jwt:
    secret-key: ${JWT_SECRET_KEY}
  • Zero Hardcoded Secrets en el archivo empaquetado .jar.
