Contenedores Non-Root, Distroless y Multi-Stage Builds en Java 25

Curso: IF0009 - Desarrollo de Software IV Profesor: Mag. Jonathan Granados C. Semestre: II-2026 | Universidad de Costa Rica

Objetivos de la Sesión

  • Comprender los riesgos de ejecutar contenedores como usuario root (UID 0).
  • Minimizar la superficie de ataque con imágenes Distroless.
  • Diseñar construcciones en múltiples etapas (Multi-Stage Builds).
  • Implementar sistemas de archivos de solo lectura (--read-only).
  • Optimizar la ejecución de la JVM en contenedores (cgroups v2).

El Peligro del Usuario root en Contenedores

  • Mito común: "Un contenedor es un entorno virtual completamente aislado".
  • Realidad Técnica:
    • El contenedor comparte el kernel del sistema anfitrión.
    • Si un proceso corre como UID 0 y sufre una brecha, puede ejecutar un Container Breakout y controlar el host.
  • Directiva Defensiva Obligatoria:
    • Crear y conmutar a un usuario no privilegiado: USER nonroot:nonroot.

Filosofía Distroless (Google Container Tools)

  • ¿Qué contiene una imagen Distroless?
    • Únicamente la JVM y bibliotecas de enlace dinámico mínimas.
    • CERO gestores de paquetes (apt, apk).
    • CERO intérpretes de shell (/bin/sh, /bin/bash).
    • CERO comandos de red (curl, wget, nc).
  • Si un atacante inyecta comandos del sistema, no tiene intérprete para ejecutarlos.

Dockerfile Multi-Stage en Java 25

# ETAPA 1: Construcción
FROM maven:3.9.6-eclipse-temurin-25 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# ETAPA 2: Runtime Seguro Distroless
FROM gcr.io/distroless/java25-debian12:nonroot
WORKDIR /app
COPY --from=builder /build/target/*.jar app.jar
USER nonroot:nonroot
ENTRYPOINT ["java", "-jar", "app.jar"]
  • Imagen final compacta y libre de código fuente o dependencias de compilación.

Parámetros de Ejecución Blindada

docker run -d \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid \
  --security-opt=no-new-privileges:true \
  --cap-drop=ALL \
  -p 8080:8080 api-segura:latest
  • --read-only: Impide alterar binarios o inyectar scripts en disco.
  • --cap-drop=ALL: Elimina privilegios del kernel no indispensables.
