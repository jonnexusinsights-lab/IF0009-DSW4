# ¿Qué es OWASP?

* **Open Web Application Security Project:** Comunidad global abierta y sin fines de lucro.
* Produce estándares, guías y herramientas para la seguridad del software.
* **Misión:** Transformar la seguridad de aplicaciones en un proceso medible y visible.
* **Consenso Global:** Referencia indiscutible para regulaciones bancarias y gubernamentales.

---

# Metodología de Estimación de Riesgos

* El riesgo técnico se cuantifica mediante la relación fundamental:
  * **Riesgo = Probabilidad × Impacto**
* **Probabilidad (Likelihood):** Facilidad técnica para descubrir y explotar el defecto.
* **Impacto (Impact):** Consecuencias sobre la confidencialidad, integridad y disponibilidad.
* **Criterio Moderno:** Incorpora prevalencia estadística real de ataques observados a nivel global.

---

# OWASP Top 10 Web (Aspectos Críticos)

* **A01: Broken Access Control:** Falla más frecuente; acceso no autorizado a datos ajenos.
* **A02: Cryptographic Failures:** Exposición de datos por cifrado obsoleto o inexistente.
* **A03: Injection:** Inyecciones SQL, NoSQL y comandos de sistema operativo.
* **A05: Security Misconfiguration:** Parámetros por defecto, puertos expuestos y debuggers activos.
* **A07: Identification and Auth Failures:** Deficiencias en manejo de credenciales y sesiones.

---

# OWASP Mobile Top 10 (Ecosistema Móvil)

* **M1: Improper Credential Usage:** Almacenamiento o transmisión descuidada de tokens.
* **M2: Inadequate Supply Chain:** Dependencias de terceros comprometidas o vulnerables.
* **M3: Insecure Communication:** Tráfico HTTP sin cifrar o vulnerable a proxies MitM.
* **M4: Insufficient Input Validation:** Explotación de esquemas de URL y llamadas IPC.
* **M9: Insecure Data Storage:** Persistencia en SharedPreferences sin cifrar o SQLite en claro.

---

# Web vs. Móvil: Diferencias de Superficie

* **Entorno Web:**
  * El código backend reside en un servidor controlado y protegido.
  * La protección perimetral (WAF, DMZ) previene acceso directo a la infraestructura.
* **Entorno Móvil:**
  * El binario reside físicamente en el dispositivo del usuario.
  * El atacante tiene acceso irrestricto: ingeniería inversa, depuradores y root.
  * Obliga a adoptar una postura de **Zero Trust** en el cliente.

# Defensa en Backend: Control de Acceso (Java 25)

```java
@RestController
@RequestMapping("/api/v1/expedientes")
public class ExpedienteController {

    @GetMapping("/{id}")
    @PreAuthorize("hasRole('ADMIN') or " +
                  "#id == authentication.principal.id")
    public ResponseEntity<ExpedienteDTO> get(
            @PathVariable Long id) {
        return ResponseEntity.ok(service.buscarPorId(id));
    }
}
```

* `@PreAuthorize` valida pertenencia estricta antes de invocar la lógica.
* Erradica vulnerabilidades IDOR de raíz en el servidor.

# Defensa en Móvil: Persistencia Segura (Flutter 3)

```dart
// Uso de hardware seguro nativo (Keystore / Keychain)
final storage = FlutterSecureStorage(
  aOptions: AndroidOptions(
    encryptedSharedPreferences: true,
  ),
);

// Escritura cifrada con AES-256
await storage.write(
  key: 'jwt_token', 
  value: tokenRecibido,
);
```

* Impide la extracción de credenciales mediante volcados de memoria o ADB.
