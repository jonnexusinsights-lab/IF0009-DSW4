# Objetivos de la Sesión

* Identificar algoritmos obsoletos e inseguros (**MD5, SHA-1, DES**).
* Implementar funciones de derivación seguras: **Argon2id** y **BCrypt**.
* Comprender la necesidad del *Salt* y el factor de costo computable.
* Prevenir ataques de temporización (*Timing Attacks*) en comparación de credenciales.

# Las Tres Ramas Criptográficas

* **1. Funciones Resumen (Hash Unidireccional):**
  * Diseñadas para contraseñas. Imposible recuperar el texto original.
  * Ejemplos seguros: **Argon2id**, **BCrypt** (cost $\ge 12$).
* **2. Cifrado Simétrico (Una sola clave):**
  * Para grandes volúmenes de datos en reposo.
  * Estándar actual: **AES-256-GCM** (cifrado autenticado AEAD).
* **3. Cifrado Asimétrico (Par de claves Pública / Privada):**
  * Para firmas digitales, certificados y negociación TLS.
  * Estándar: **RSA $\ge 2048$ bits** y Curvas Elípticas (**ECC / Ed25519**).

---

# ¿Por qué NUNCA usar SHA-256 para contraseñas?

* **SHA-256 es un algoritmo de alta velocidad:**
  * Diseñado para verificar integridad de archivos y bloques de datos.
  * Una tarjeta GPU moderna calcula $>10$ mil millones de hashes por segundo.
  * Permite romper contraseñas con tablas arcoíris (*Rainbow Tables*) en minutos.
* **Solución (Argon2id / BCrypt):**
  * Incorporan **Salting** aleatorio por cada usuario.
  * Introducen **Work Factor** y consumo de memoria RAM intencional.
  * Hacen que cada verificación tome 200-500 ms, volviendo inviable la fuerza bruta.

# Configuración de Argon2id en Spring Boot (Java 25)

```java
@Configuration
public class CriptografiaConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new Argon2PasswordEncoder(
            16,     // Longitud del salt (16 bytes)
            32,     // Longitud del hash resultante
            1,      // Hilos paralelos de CPU
            65536,  // Consumo de RAM: 64 MB
            3       // Iteraciones computacionales
        );
    }
}
```

* Recomendación oficial de NIST y OWASP Password Storage Cheat Sheet.

# Verificación Segura en Tiempo Constante

```java
@Transactional(readOnly = true)
public boolean validarCredenciales(String email, String rawPass) {
    Usuario user = repository.findByEmail(email)
        .orElseThrow(() -> new BadCredentialsException());

    // Compara en tiempo constante (previene Timing Attacks)
    return passwordEncoder.matches(rawPass, user.getPasswordHash());
}
```

* `matches()` no retorna antes de tiempo si el primer byte falla.
* Evita que atacantes midan microsegundos para adivinar caracteres.

# Errores Críticos que Debe Evitar

* **Algoritmos deprecados:** Usar MD5 o SHA-1 en nuevos proyectos.
* **Modo AES-ECB:** Permite visualizar patrones de datos repetidos. Use siempre **AES-GCM**.
* **Hardcoded Keys:** Quemar claves criptográficas en el código Java o TypeScript.
* **Falta de Salt:** Hashear contraseñas idénticas genera hashes idénticos en la base de datos.
