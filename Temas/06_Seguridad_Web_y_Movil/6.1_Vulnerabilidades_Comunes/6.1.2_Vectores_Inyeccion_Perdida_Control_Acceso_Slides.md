# Anatomía de una Inyección SQL

* **Causa Raíz:** Mezcla indeseada entre instrucciones sintácticas y datos externos.
* **Vector Clásico:** Concatenación de cadenas en controladores o DAOs:
  `"SELECT * FROM usuarios WHERE email = '" + email + "'"`
* Si `email = ' OR '1'='1`, la consulta altera su árbol sintáctico lógico.
* **Consecuencias:**
  * Evasión total de pantallas de login.
  * Extracción masiva de bases de datos (*Data Breach*).
  * Modificación o destrucción de tablas (`DROP TABLE`).

# Antipatrón vs. Remediación en Java 25

```java
// INSEGURO: Concatenación directa
String sql = "SELECT u FROM Usuario u WHERE u.email = '" + email + "'";
return em.createQuery(sql, Usuario.class).getResultList();

// SEGURO: Parámetro nombrado en Spring Data JPA
@Query("SELECT u FROM Usuario u WHERE u.email = :email")
Optional<Usuario> buscarPorEmail(@Param("email") String email);
```

* El compilador de base de datos precompila el plan de ejecución.
* El valor de `:email` se trata estrictamente como un literal textual.

# Broken Access Control (OWASP #1)

* Ocurre cuando las restricciones de permisos no se aplican en el servidor.
* **Escalamiento Vertical:**
  * Usuario regular accede a `/api/admin/usuarios` sin rol `ROLE_ADMIN`.
* **Escalamiento Horizontal (IDOR):**
  * Usuario autenticado `10` cambia la URL a `/api/recibos/25` (perteneciente a usuario `20`).
  * El servidor valida que el token sea válido, pero no valida la pertenencia del recibo.

---

# Mitigación de IDOR en la Capa de Negocio

```java
@Transactional(readOnly = true)
public Expediente consultarSeguro(Long idExpediente) {
    Expediente exp = repository.findById(idExpediente)
        .orElseThrow(() -> new NotFoundException());

    String usuarioActual = SecurityContextHolder.getContext()
        .getAuthentication().getName();

    if (!exp.getCreadoPor().equals(usuarioActual)) {
        throw new AccessDeniedException("Acceso no autorizado.");
    }
    return exp;
}
```

* Regla dorada: La autorización debe comprobar la propiedad del recurso.

---

# Trampas Comunes en Arquitectura

* **"Uso JPA, por lo tanto soy inmune":** Concatenar cadenas dentro de `@Query(value = "...", nativeQuery = true)` reintroduce la vulnerabilidad.
* **Seguridad por Oscuridad (UUIDs):** Usar identificadores alfanuméricos largos mitiga la adivinanza por fuerza bruta, pero no previene IDOR si el identificador es descubierto.
* **Proteger solo consultas (GET):** Descuidar endpoints `DELETE` o `PUT`, permitiendo manipulación no autorizada.
