# Los Tres Tipos de XSS

* **1. XSS Almacenado (Stored):**
  * El script se guarda en la base de datos (foros, perfiles).
  * Se ejecuta en el navegador de cada usuario que abra la vista.
* **2. XSS Reflejado (Reflected):**
  * El script viaja en un parámetro de la URL y el servidor lo devuelve en el HTML.
  * Requiere engañar a la víctima para hacer clic en un enlace.
* **3. XSS Basado en DOM:**
  * La vulnerabilidad ocurre en el JavaScript del cliente (ej. `element.innerHTML = hash`).

---

# Codificación Dependiente del Contexto

* El navegador tiene múltiples analizadores sintácticos. Cada uno requiere su propio escape:
  * **Cuerpo HTML:** `&` $\to$ `&amp;`, `<` $\to$ `&lt;`, `>` $\to$ `&gt;`.
  * **Atributos HTML:** `"` $\to$ `&quot;`, `'` $\to$ `&#x27;`.
  * **Literales JavaScript:** Secuencias de escape Unicode (`\u0027`).
  * **URLs:** `encodeURIComponent()` estricto.

# Angular 17+: Seguridad por Defecto

```typescript
// Seguro por defecto: Angular neutraliza cualquier script
<div>{{ comentarioUsuario }}</div>

// PELIGROSO: Desactivar la seguridad de Angular
get contenidoInseguro(): SafeHtml {
  return this.sanitizer.bypassSecurityTrustHtml(this.comentario);
}
```

* La interpolación `{{ }}` escapa automáticamente cualquier tag o atributo hostil.
* Nunca utilice `bypassSecurityTrustHtml` con datos provenientes de usuarios externos.

---

# ¿Por qué Flutter es Inmune a XSS Nativo?

* **Arquitectura de Renderizado Propia:**
  * Flutter no traduce sus widgets a elementos HTML del DOM.
  * Utiliza su propio motor gráfico (**Impeller / Skia**) dibujando píxeles en la GPU.
* Un widget `Text('<script>alert(1)</script>')` se renderiza visualmente como texto plano.
* **Excepción:** Vistas web incrustadas (`WebView`), donde sí aplican las reglas de seguridad web.

---

# Buenas Prácticas Fundamentales

* **Cookies con bandera `HttpOnly`:** Impide que cualquier script inyectado pueda robar la sesión.
* **Uso de Content Security Policy (CSP):** Bloquea la ejecución de scripts no autorizados.
* **Validación en Backend:** Rechazar entradas maliciosas antes de que lleguen a la base de datos.
