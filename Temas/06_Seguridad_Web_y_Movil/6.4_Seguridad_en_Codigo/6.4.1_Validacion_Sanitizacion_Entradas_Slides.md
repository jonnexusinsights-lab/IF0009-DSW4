# Regla de Oro de la Entrada de Datos

* **Principio de Desconfianza Absoluta:**
  * *Toda entrada de red debe considerarse hostil hasta demostrar lo contrario.*
* **Validación vs. Sanitización:**
  * **Validación:** Comprueba si el dato es aceptable. Si falla, **se rechaza** (HTTP 400).
  * **Sanitización:** Modifica o escapa caracteres peligrosos antes de persistir.
* **Allowlisting (Lista Blanca):**
  * Define con rigor lo que está permitido (ej. `^[a-zA-Z0-9_]{3,20}$`).
  * Las listas negras son eludibles mediante variantes de codificación.

# Validador Personalizado en Java 25

```java
public class CedulaValidator 
        implements ConstraintValidator<CedulaCostarricense, String> {

    private static final Pattern PATRON = Pattern.compile("^[1-9]\\d{8}$");

    @Override
    public boolean isValid(String valor, ConstraintValidatorContext ctx) {
        if (valor == null || valor.isBlank()) return false;
        return PATRON.matcher(valor).matches();
    }
}
```

* Encapsula la regla sintáctica y semántica en una anotación reutilizable.

# Java 25 Records con Bean Validation

```java
public record RegistrarClienteDTO(
    @NotBlank(message = "El nombre no puede quedar vacío")
    @Size(min = 2, max = 80)
    String nombre,

    @CedulaCostarricense
    String cedula,

    @NotBlank @Email
    String email
) {}
```

* Inmutabilidad garantizada por el compilador de Java.
* Validación automática al invocar el endpoint con `@Valid`.

# Respuestas Estándar con RFC 7807 (`ProblemDetail`)

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
public ProblemDetail manejarErrores(MethodArgumentNotValidException ex) {
    ProblemDetail pd = ProblemDetail.forStatusAndDetail(
        HttpStatus.BAD_REQUEST, "Infracciones de validación encontradas.");
    pd.setTitle("Entrada Inválida");
    pd.setProperty("infracciones", mapearErrores(ex));
    return pd;
}
```

* Proporciona un formato estructurado universal para clientes Flutter y Angular.
