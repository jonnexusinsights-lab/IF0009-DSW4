# El Principio de Von Neumann y las Inyecciones

* **Causa Raíz:**
  * En la arquitectura Von Neumann, el código ejecutable y los datos conviven en el mismo canal.
  * Si un dato externo contiene caracteres de control sintáctico, el intérprete altera su Árbol de Sintaxis Abstracta (AST).
* **La Solución Universal:**
  * **Precompilación Estricta:** Compilar primero la estructura fija del AST.
  * Los parámetros dinámicos se transportan como literales aislados sin capacidad de ejecución.

---

# Inyecciones Ciegas (Blind SQLi)

* Ocurren cuando la aplicación no despliega errores SQL ni datos directos en pantalla.
* **1. Blind Booleana:**
  * `AND (SELECT SUBSTRING(pass, 1, 1) FROM admin) = 'a'`
  * Infiere el dato carácter a carácter según si la app responde con éxito o error general.
* **2. Blind Basada en Tiempo:**
  * `AND IF(1=1, SLEEP(5), 0)` (MySQL) o `WAITFOR DELAY '0:0:5'` (SQL Server).
  * Si el servidor responde 5 segundos después, el atacante confirma su hipótesis.

---

# El Gran Peligro: `ORDER BY` Dinámico

* Las columnas de ordenamiento **NO se pueden parametrizar** con `?` en JDBC.
* **Solución Defensiva (Lista Blanca / Allowlisting):**

```java
private static final Set<String> COLUMNAS = Set.of("id", "nombre", "fecha");

public Sort crearOrdenSeguro(String columna, String dir) {
    if (!COLUMNAS.contains(columna)) {
        throw new SecurityException("Columna inválida.");
    }
    return Sort.by(Sort.Direction.fromString(dir), columna);
}
```

* Rechaza cualquier intento de inyección en la cláusula de ordenamiento.

---

# Inyección NoSQL en Documentos JSON

* Ocurre cuando se aceptan objetos arbitrarios en lugar de tipos escalares:
  ```json
  { "usuario": "admin", "password": { "$ne": null } }
  ```
  *(Operador $ne = "No es nulo", evaluando a Verdadero).*
* **Mitigación en Java 25:**
  * Tipar con Java Records: `public record LoginDTO(String user, String pass) {}`.
  * Jackson aborta si el cliente envía un objeto anidado en lugar de una cadena.
