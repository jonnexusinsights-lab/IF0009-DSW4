# Tema 5.1.2: Flutter - De Principiante a Avanzado

Flutter es el UI Toolkit de código abierto creado por Google para construir aplicaciones compiladas nativamente para Móvil, Web y Escritorio a partir de una única base de código. 

A diferencia de React Native, Flutter no utiliza un puente (bridge) para comunicarse con los componentes (OEM) del dispositivo. En su lugar, Flutter pinta la interfaz gráfica completa píxel por píxel utilizando su motor gráfico de alto rendimiento (Skia o el nuevo Impeller).

---

## 1. El Lenguaje: Dart 3

Flutter utiliza **Dart**, un lenguaje orientado a objetos, fuertemente tipado y optimizado para el desarrollo de interfaces de usuario (UI). Con la llegada de Dart 3, el lenguaje soporta características avanzadas de programación funcional.

### 1.1 Null Safety Estricto
Dart asegura que ninguna variable pueda contener un valor nulo a menos que se declare explícitamente con `?`. Esto elimina de raíz el "Billion Dollar Mistake" (NullPointerException).
```dart
String nombre = "Jonathan"; // Nunca será nulo
String? apellido = null;    // Puede ser nulo
```

### 1.2 Records (Tuplas) y Pattern Matching (Dart 3)
Permiten devolver múltiples valores de una función sin crear una clase, y destructurarlos fácilmente.

```dart
// Retornar un Record
(String, int) obtenerUsuario() {
  return ("Maria", 25);
}

// Pattern Matching en la asignación
var (nombre, edad) = obtenerUsuario();

// Switch Expressions (Pattern Matching)
String categoria = switch(edad) {
  < 18 => 'Menor',
  >= 18 && <= 65 => 'Adulto',
  _ => 'Mayor'
};
```

## 2. El Árbol de Widgets (The Widget Tree)

En Flutter, **Todo es un Widget**. 
Un botón es un Widget. El padding es un Widget. El posicionamiento es un Widget. La aplicación entera es un Widget.

### 2.1 StatelessWidget vs StatefulWidget
*   **StatelessWidget:** Una vista inmutable. Se dibuja una vez basado en la configuración recibida y no cambia internamente (Ej. un Texto estático o un Ícono).
*   **StatefulWidget:** Una vista que contiene un objeto de estado interno (`State`). Cuando el estado cambia (mediante la llamada a `setState()`), el widget ordena a Flutter que redibuje esa porción específica de la pantalla (Ej. un Checkbox o un Contador).

### 2.2 Layouts Básicos
Los contenedores más usados para organizar la UI:
*   `Container`: Una caja para colorear, aplicar márgenes (margin) y bordes.
*   `Row`: Alinea a sus hijos horizontalmente.
*   `Column`: Alinea a sus hijos verticalmente.
*   `Stack`: Superpone widgets uno encima de otro (Z-Index).

## 3. Arquitecturas de Gestión de Estado (State Management)

A medida que la aplicación crece, pasar variables de widget padre a widget hijo (Prop Drilling) se vuelve insostenible. Necesitamos sacar la lógica de negocio de la UI.

### 3.1 Provider
Es el gestor de estado estándar y más recomendado por Google para proyectos de tamaño mediano. Utiliza `ChangeNotifier`. La UI "escucha" (listens) los cambios de la clase.

### 3.2 Riverpod
Creado por el mismo autor de Provider, pero diseñado para resolver sus defectos (como errores en tiempo de ejecución por no encontrar el Provider en el árbol). Riverpod es seguro en tiempo de compilación y es el estándar de oro en aplicaciones modernas.

### 3.3 BLoC (Business Logic Component)
La arquitectura más avanzada y corporativa. Basada estrictamente en **Streams (Flujos de Datos Asíncronos)**.
*   La UI dispara **Eventos**.
*   El BLoC recibe el evento, procesa la lógica de negocio, y emite un nuevo **Estado**.
*   La UI reacciona al nuevo estado y se redibuja.

## 4. Conceptos Avanzados: Asincronía, Isolates y Plataforma

### 4.1 Consumo HTTP Asíncrono
Dart es *Single-Threaded* (de un solo hilo) utilizando un Event Loop (similar a NodeJS). Se usa `async / await` y clases como `Future` para llamadas de red sin bloquear la interfaz.

```dart
Future<List<Post>> fetchPosts() async {
  final response = await http.get(Uri.parse('https://api.com/posts'));
  if (response.statusCode == 200) {
    return parseJson(response.body);
  } else {
    throw Exception('Failed to load posts');
  }
}
```

### 4.2 Isolates (Multihilo Real)
Dado que el parseo de JSON gigante bloquea el Event Loop y causa caída de FPS (Jank), Flutter permite usar **Isolates**. Un Isolate es un espacio de memoria completamente separado que corre en otro hilo físico del procesador. Se comunican por paso de mensajes.
`compute(parseJson, response.body)` envía el trabajo pesado a un Isolate.

### 4.3 MethodChannels (Canales de Plataforma)
Cuando Flutter necesita acceder a un SDK nativo para el cual no existe un paquete (ej. un POS de pago Bluetooth de un banco local), se usan `MethodChannels`. Permiten escribir código en Swift (iOS) o Kotlin (Android) y enviarle comandos directamente desde el código Dart.

## 5. Resumen
Flutter cambia el paradigma móvil unificando el motor de renderizado. Escalar una aplicación en Flutter desde un "Hola Mundo" hasta un nivel empresarial (Advanced) implica:
1. Dominar Dart 3 (Null Safety y Pattern Matching).
2. Entender que el árbol de Widgets debe ser inmutable y pequeño.
3. Desacoplar la vista mediante una arquitectura de estado (Riverpod o BLoC).
4. Mover la carga matemática pesada a hilos en segundo plano (Isolates).
