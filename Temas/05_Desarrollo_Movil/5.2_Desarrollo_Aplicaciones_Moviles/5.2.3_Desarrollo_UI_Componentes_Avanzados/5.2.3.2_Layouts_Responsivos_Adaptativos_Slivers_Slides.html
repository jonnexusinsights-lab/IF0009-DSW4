Objetivos de la Sesión

  • Analizar trade-offs de rendimiento entre MediaQuery y LayoutBuilder.
  • Diseñar interfaces adaptativas para móvil, tableta y escritorio.
  • Comprender la arquitectura de Slivers y su protocolo de desplazamiento.
  • Implementar listas virtualizadas y cabeceras dinámicas con CustomScrollView.

La Regla de Oro del Renderizado

  • 1. Constraints go down: El widget padre impone límites de tamaño (minW, maxW, minH, maxH).
  • 2. Sizes go up: El widget hijo calcula sus propias dimensiones dentro de esos límites.
  • 3. Parent sets position: El padre asigna la coordenada (x, y) final del hijo.
  • Algoritmo de Una Sola Pasada: Complejidad de maquetación $O(N)$ de ultra alto rendimiento.

MediaQuery vs LayoutBuilder

  • MediaQuery.sizeOf(context):
    • Obtiene las dimensiones globales de la pantalla o ventana.
    • Reconstruye cuando la ventana cambia (rotación, teclado virtual).
    • Ideal para decisiones a nivel de pantalla raíz.
  • LayoutBuilder:
    • Inspecciona las restricciones locales que impone el contenedor padre.
    • Reconstruye de forma aislada solo cuando sus restricciones varían.
    • Esencial para componentes modulares y reutilizables.

El Paradigma de los Slivers

  • Limitación de Listas Tradicionales: ListView opera en una caja con dimensiones fijas.
  • ¿Qué es un Sliver? Una porción de pantalla desplazable gobernada por SliverConstraints.
  • Viewport Unificado: CustomScrollView permite combinar listas, grids y headers.
  • Virtualización Estricta: Destruye y recicla elementos invisibles en memoria.

Componentes Clave de Slivers

  • SliverAppBar: Cabecera con efectos de colapso, estiramiento y anclaje (pinned).
  • SliverList: Lista lineal con generador delegado (SliverChildBuilderDelegate).
  • SliverGrid: Cuadrícula de elementos adaptable por número de columnas o ancho máximo.
  • SliverToBoxAdapter: Puente para incrustar widgets tradicionales (Container, Card).

Implementación: CustomScrollView

CustomScrollView(
  physics: const BouncingScrollPhysics(),
  slivers: [
    SliverAppBar(
      expandedHeight: 200.0,
      pinned: true,
      flexibleSpace: FlexibleSpaceBar(
        title: Text('Catálogo IF0009'),
        background: HeaderGradientWidget(),
      ),
    ),
    SliverToBoxAdapter(
      child: SectionTitleWidget('Módulos Disponibles'),
    ),
    SliverList(
      delegate: SliverChildBuilderDelegate(
        (context, index) => ProductCard(items[index]),
        childCount: items.length,
      ),
    ),
  ],
)

Adaptabilidad con SliverLayoutBuilder

SliverLayoutBuilder(
  builder: (context, constraints) {
    // Si el ancho supera 600px, mostrar cuadricula de 3 columnas
    if (constraints.crossAxisExtent >= 600) {
      return SliverGrid(
        gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(
          crossAxisCount: 3,
          childAspectRatio: 1.8,
        ),
        delegate: SliverChildBuilderDelegate(
          (context, i) => ProductCard(items[i]),
          childCount: items.length,
        ),
      );
    }
    // Pantallas compactas (moviles): Lista vertical simple
    return SliverList(
      delegate: SliverChildBuilderDelegate(
        (context, i) => ProductCard(items[i]),
        childCount: items.length,
      ),
    );
  },
)

Trampas Comunes de Maquetación

  • "Vertical viewport was given unbounded height": Incrustar ListView dentro de Column sin Expanded.
  • Abuso de shrinkWrap: true: Desactiva la virtualización y renderiza miles de ítems a la vez.
  • Over-rebuilding con MediaQuery: Invocar MediaQuery.of(context) en la raíz sin selectores específicos.
  • Forzado de Dimensiones: Intentar forzar width en un hijo cuando el padre tiene una restricción estricta (tight).
