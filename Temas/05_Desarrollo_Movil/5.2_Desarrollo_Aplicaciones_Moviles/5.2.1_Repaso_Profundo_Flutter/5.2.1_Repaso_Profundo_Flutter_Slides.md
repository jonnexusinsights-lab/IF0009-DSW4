# 1. Arquitectura de Flutter: Skia vs Impeller

* **Sin Puentes de Serialización:** Flutter no usa puente JSON (a diferencia de React Native clásico) ni WebViews.
* **Compilación Native AOT:** El código Dart se compila a binario nativo (ARM64 / x86_64).
* **Motor Gráfico Skia:** Histórico motor 2D, sujeto a *Shader Compilation Jank*.
* **Motor Gráfico Impeller:** Diseñado para iOS/Android moderno, precompila shaders en build-time para garantizar 60/120 FPS constantes.

---

# 2. La Arquitectura de los Tres Árboles

Flutter mantiene 3 estructuras paralelas en memoria:

```
[ Widget Tree ]  -->  Inmutable / Configuración Declarativa
       |
[ Element Tree ] -->  Mutable / Estructura & Estado en Memoria
       |
[ RenderObject ] -->  Mutable / Geometría, Layout & Pintado GPU
```

* **Regla de Oro del Layout (Single-Pass):**
  > *Constraints Go Down. Sizes Go Up. Parent Sets Position.*

# 4. Ciclo de Vida de un `StatefulWidget`

```
  Constructor
      ↓
  createState()
      ↓
   initState()          <-- (1 sola vez: Subscripciones / Init)
      ↓
didChangeDependencies() <-- (Cambios en InheritedWidget / Theme)
      ↓
    build()             <-- (Se re-ejecuta al llamar setState)
      ↓
  deactivate()
      ↓
   dispose()            <-- (Destrucción: Limpieza de Memory Leaks)
```

# Live Coding: `initState` y `dispose`

```dart
class _MonitorMedicoWidgetState extends State<MonitorMedicoWidget> 
    with WidgetsBindingObserver {
  int _frecuencia = 75;

  @override
  void initState() {
    super.initState();
    WidgetsBinding.instance.addObserver(this);
  }

  @override
  void dispose() {
    WidgetsBinding.instance.removeObserver(this);
    super.dispose();
  }
}
```

# 6. Paradigmas de Gestión de Estado

| Patrón | Enfoque | Uso Recomendado |
|---|---|---|
| **setState()** | Estado Local | Widgets efímeros aislados (ej. checkbox, toggle). |
| **Provider** | ChangeNotifier / Inherited | Aplicaciones de tamaño pequeño-mediano. |
| **BLoC / Cubit** | Reactive Streams (Event->State) | Sistemas empresariales desacoplados y testeables. |
| **Riverpod** | Reactividad Funcional | Proyectos escalables sin dependencia de BuildContext. |

# 7. Reglas de Optimización de Rendimiento

1. **Usar `const` siempre que sea posible:** Reutiliza instancias en memoria y omite llamadas a `build()`.
2. **Asignar `Keys` (`ValueKey`):** En listas dinámicas reordenables para mantener la sincronización con el `Element Tree`.
3. **Extraer sub-widgets en clases `StatelessWidget`:** Evitar métodos auxiliares `_buildChild()` dentro de la misma clase.
4. **Utilizar `RepaintBoundary`:** Para aislar animaciones complejas en capas compuestas independientes de GPU.
