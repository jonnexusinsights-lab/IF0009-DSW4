# Evolución de las Sesiones Web

* **Enfoque Basado en Estado (Stateful):**
  * Servidor almacena la sesión en memoria (`HttpSession` / `JSESSIONID`).
  * Dificulta el escalado horizontal de microservicios.
  * Vulnerable a ataques CSRF si se apoya únicamente en cookies.
* **Enfoque Sin Estado (Stateless):**
  * Servidor **no almacena nada** en memoria.
  * Emite credenciales autónomas en cada solicitud: **JSON Web Tokens (JWT)**.
  * Facilita el escalamiento elástico de microservicios.

# Anatomía de un JSON Web Token (RFC 7519)

Cadena compacta dividida en 3 partes por puntos: `HEADER.PAYLOAD.SIGNATURE`

1. **Header (Encabezado):** Algoritmo (`HS256`) y tipo (`JWT`) en Base64Url.
2. **Payload (Carga Útil):** Claims del usuario (`sub`, `exp`, `roles`) en Base64Url. *(¡Es público, no incluya contraseñas!)*
3. **Signature (Firma):** HMAC-SHA256 del Header + Payload con la clave secreta. Garantiza la integridad infalsificable.

# Generación de Tokens: `JwtTokenProvider`

```java
@Component
public class JwtTokenProvider {

    public String generarToken(Authentication authentication) {
        String username = authentication.getName();
        Date ahora = new Date();
        Date expiracion = new Date(ahora.getTime() + jwtExpirationInMs);

        return Jwts.builder()
            .subject(username)
            .claim("roles", obtenerRoles(authentication))
            .issuedAt(ahora)
            .expiration(expiracion)
            .signWith(key)
            .compact();
    }
}
```

# Intercepción de Peticiones: `JwtAuthenticationFilter`

```java
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, 
                                    FilterChain chain) throws ServletException, IOException {
        String token = obtenerJwt(req);
        if (StringUtils.hasText(token) && tokenProvider.validarToken(token)) {
            String username = tokenProvider.obtenerUsernameDelJWT(token);
            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            UsernamePasswordAuthenticationToken auth = 
                new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        chain.doFilter(req, res);
    }
}
```

# Configuración Stateless en Spring Security

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(sess -> sess
            .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
        )
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/**").permitAll()
            .anyRequest().authenticated()
        )
        .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)
        .build();
}
```

# Trampas Comunes y Buenas Prácticas

* **Claves Secretas Débiles:** Deben tener al menos 256 bits (32 caracteres) de entropía. Cárguelas desde variables de entorno.
* **Payload No Encriptado:** Nunca coloque contraseñas o datos médicos en el Payload.
* **Almacenamiento en Cliente:** Proteja contra XSS. Use cookies `HttpOnly` y `SameSite=Strict` cuando sea viable.
