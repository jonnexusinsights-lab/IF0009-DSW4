## 📚 Contenidos Evaluados (Módulos 1 a 4 Completos)

### 1. Tema 1: Fundamentos de Desarrollo Web y Arquitectura Full-Stack
* Arquitecturas cliente-servidor (MPA vs SPA), desacoplamiento de capas, conceptos de rendimiento cliente/servidor (CSR vs SSR) y criterios de selección de stacks tecnológicos.

### 2. Tema 2: Configuración del Ambiente de Desarrollo y Git
* Control de versiones con Git en rama principal `main`, estrategia de ramas de características (*Feature Branching*), mensajes de commit semánticos, archivo `.gitignore` y solución de conflictos.

### 3. Tema 3: Desarrollo Back-End Completo
* Spring Boot 3 en Java 21, entidades relacionales JPA, repositorios JPQL paginados (`Pageable`), validaciones de negocio, manejador global de excepciones RFC 7807 (Problem Details), seguridad JWT RFC 7519, control de acceso por roles (RBAC) y pruebas unitarias con JUnit 5 Jupiter / Mockito.

### 4. Tema 4: Desarrollo Front-End Completo
* HTML5 semántico, accesibilidad web (WCAG 2.1 AA), CSS3 (Flexbox y CSS Grid Layout), diseño Mobile-First, TypeScript avanzado, componentes standalone en Angular 19, Signals (`signal()`, `computed()`), control de flujo moderno y consumo asíncrono de APIs RESTful.

## ⚠️ Reglas e Instrucciones Obligatorias

**1. Prohibición Estricta de Herramientas de IA Generativa:**  
Queda absolutamente prohibido el uso de asistentes de IA generativa (ChatGPT, GitHub Copilot, Claude, Gemini, etc.). No hay ninguna herramienta de IA permitida durante la prueba. La detección de código o contenido generado por IA invalidará la prueba inmediatamente de acuerdo con el Reglamento de Orden y Disciplina de la UCR.

**2. Sin Acceso a Documentación Oficial o Recursos Externos:**  
El examen evaluará el conocimiento práctico acumulado durante las sesiones lectivas. No se permitirá la consulta de documentación oficial en línea (MDN, Spring Docs, Angular Docs), repositorios previos de clases, notas ni páginas de terceros durante la resolución del examen.

**3. Uso Obligatorio de Git y GitHub con Commits Frecuentes:**  
La solución debe versionarse desde el inicio de la prueba realizando *commits* semánticos individuales periódicos en la cuenta institucional de GitHub del estudiante. Se auditará el historial y marca de tiempo de cada commit para certificar la autoría.

**4. Puntualidad Estricta:**  
El acceso a la plataforma Mediación Virtual y a las instrucciones del examen se habilitará estrictamente a la 1:00 PM en el Laboratorio de Cómputo 3. No se otorgará tiempo adicional por llegadas tardías.
