• Modela métodos principales de negocio, firmas de parámetros y tipos de retorno.
• Expresa relaciones formales de agregación, composición y dependencias de inyección entre componentes Spring. 		Diagrama UML legible en formato PDF o imagen de alta resolución. 8 pts

Componente 2: Proyecto Funcional Desarrollado y Defensa

Implementación de código fuente en GitHub + Sustentación individual
75 Puntos (75%)
Criterio Evaluativo Descriptores de Calidad (Excelente) Evidencias de Evaluación Puntaje
2.1 Backend Spring Boot 3 y Persistencia Java 17/21 • Data JPA • JWT • Separación estricta de responsabilidades en capas (Controller, Service, Repository, Entity).
• Mapeo relacional con Spring Data JPA sin incidencias de consultas N+1 (uso de JOIN FETCH o @EntityGraph).
• Lógica de negocio en capa de servicios: validación determinista de traslapes de horario y control de cancelación previa (2h).
• Manejo global de excepciones mediante @RestControllerAdvice bajo el estándar RFC 7807.
• Seguridad robusta con Spring Security: autenticación stateless y tokens JWT con control por roles. 		Ejecución de la API REST, pruebas de traslapes en Swagger/Postman y revisión de consultas SQL en consola. 25 pts
(25%)
2.2 Frontend Angular SPA, Accesibilidad e i18n Angular v17+ Standalone • Estructura basada en Standalone Components (sin NgModules monolíticos).
• Formularios Reactivos (ReactiveFormsModule) fuertemente tipados con retroalimentación visual accesible ante errores de validación.
• Enrutamiento modular con guardas funcionales (CanActivateFn) y HttpInterceptorFn para inyección automática de cabeceras Bearer JWT.
• Auditoría Google Lighthouse ≥ 90 en Accesibilidad (contrastes WCAG, foco de teclado, labels semánticos).
• Soporte funcional de internacionalización dinámica (i18n) con alternancia interactiva entre Español e Inglés. 		Navegación en vivo por la SPA, reporte de Lighthouse en Chrome DevTools y prueba de cambio de idioma. 20 pts
(20%)
2.3 Calidad Git, PRs y Pruebas Unitarias GitHub Flow • JUnit 5 • Mockito • Gobernanza colaborativa en GitHub: cero commits directos en main, estrategia de ramas feature/* activa y verificable.
• Evidencia explícita de Pull Requests revisados y aprobados formalmente entre compañeros de equipo.
• Batería de pruebas unitarias automatizadas con JUnit 5 y Mockito para la capa de servicios del backend, validando al menos 2 escenarios críticos de negocio (reserva exitosa vs. rechazo por conflicto de horario). 		Historial de PRs/Commits en GitHub y ejecución de mvn test con resultados en verde. 10 pts
(10%)
2.4 Defensa Oral y Live Coding Evaluación Individual con Docente • Dominio conceptual completo: el estudiante explica con fluidez la arquitectura, el flujo de datos y las decisiones tomadas en el proyecto.
• Demostración convincente de autoría individual sobre las partes del código que le fueron asignadas.
• Resolución exitosa del reto en vivo (Live Coding): modificación o extensión menor del backend o frontend solicitada por el docente durante la entrevista sincrónica. 		Entrevista oral individual, explicación técnica y codificación en pantalla compartida. 20 pts
(20%)

Resumen Consolidado del Proyecto

Diseño (25%) + Desarrollo Funcional (45%) + Gobernanza/Pruebas (10%) + Defensa Oral Individual (20%).

Calificación Máxima: 100 Puntos (30% de la nota final)
⚠️ Políticas Importantes de Aceptación:
  • El proyecto debe compilar y ejecutarse localmente según las instrucciones del README.md. Proyectos que no compilen no podrán ser evaluados.
  • La defensa oral individual es estrictamente obligatoria. La nota del Live Coding es individual para cada miembro del equipo.
  • Se comprobará la trazabilidad de autoría en GitHub; no se asignará puntaje de desarrollo a miembros con contribuciones ausentes o delegadas en commits de terceros.
